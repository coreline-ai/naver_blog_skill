# 네이버 블로그 제목 최적화

## 목표

검색과 홈피드의 발견 방식을 구분해 제목을 만든다.

- **검색형:** 사용자가 입력할 대상·행동 의도·결정 변수를 빠르게 식별하게 한다.
- **홈판형:** 독자 상황·갈등·변화·결과를 보여 클릭할 이유를 만든다.
- **혼합형:** 검색 핵심어를 앞에 두고, 뒤에 구체적인 클릭 이유를 붙인다.

`행동형 키워드`는 실무적 표현일 뿐 네이버가 발표한 공식 순위 요소로 취급하지 않는다. `신청하기`, `환불하기`, `예매하기` 같은 특정 어미를 붙이는 것을 최적화로 오해하지 말고 문맥상 검색 의도와 정보 가치를 판단한다.

## 워크플로

1. 입력에서 **대상, 독자 상황, 행동 의도, 결정 변수, 확인된 사실, 말투**를 추출한다.
2. 확인된 사실과 미확인 주장을 분리한다. 날짜·금액·순위·수수료·품절·희소성·성과를 추측하지 않는다.
3. 일반 요청에서 사용자가 유형과 개수를 지정하지 않으면 검색형 5개, 홈판형 5개, 혼합형 3개를 만든다. 단축 호출은 아래 전용 규칙을 따른다. 요청한 개수와 유형이 있으면 그 요청을 우선한다.
4. 후보마다 표현 구조를 다양화한다. 같은 제목에서 조사나 어미만 바꾼 후보를 여러 개 만들지 않는다.
5. 사실성, 제목-본문 일치, 자연스러움, 과장 위험을 검수한 뒤 목적별 최종 추천을 고른다.

본문 정보가 없어도 안전한 일반 표현으로 만들 수 있으면 질문하지 않는다. 특정 경험·수치·규정이 제목의 핵심인데 근거가 없을 때만 짧게 확인하거나 `[확인 필요]`로 표시한다.

## 단축 호출

사용자가 아래 문구로 시작한 뒤 주제어를 입력하면 `$naver-title`의 단축 호출로 해석한다.

- `네이버 제목 ...`
- `네이버 타이틀 ...`
- `네이버 주제 ...`

예:

```text
네이버 제목 여수밤바다 브런치 카페 무료주차장
```

추가 조건이나 개수가 없으면 별도 진단과 장황한 설명 없이 반드시 다음 형식으로 답한다.

```markdown
검색형 4개 :
1. ...
2. ...
3. ...
4. ...

홈판형 3개 :
1. ...
2. ...
3. ...

혼합형 3개 :
1. ...
2. ...
3. ...

최종 추천 :
...
```

사용자가 `홈합형`이라고 적으면 `혼합형`의 오타로 해석한다. 최종 출력 표기는 `혼합형`으로 통일한다. 최종 추천은 후보 중 하나를 그대로 선택하며, 사용자가 이유를 요구하지 않으면 설명을 붙이지 않는다.

## 작성 규칙

### 검색형

- 기본 구조: `대상 + 행동/문제 + 조건·비용·기간·순서 등 결정 변수`
- 핵심 대상과 의도를 제목 앞부분에 배치한다.
- 정확히 같은 키워드 반복보다 자연스러운 형태소와 동의 표현을 우선한다.
- `총정리`, `완벽`, `꿀팁`을 정보 구체성의 대체재로 사용하지 않는다.
- 고정 글자 수를 강제하지 않는다. 모바일에서 핵심이 한눈에 보이도록 보통 두 절 이내로 정리한다.

### 홈판형

- 기본 구조: `구체적인 상황 + 갈등·변화·결과 + 정직한 정보 공백`
- 막연한 `이것`, `대박`, `충격`보다 독자가 알아볼 상황과 이해득실을 제시한다.
- 입력에 없는 1인칭 경험, 전문가 권위, 사회적 증거, 품절·대기·실패 사례를 만들어내지 않는다.
- 답을 완전히 감추기보다 본문에서 받을 핵심 보상을 예고한다.

### 혼합형

- 기본 구조: `검색 핵심어｜구체적인 차이·실수·판단 기준`
- 앞 절만 읽어도 주제를 알 수 있어야 하고, 뒤 절은 반복이 아니라 추가 가치를 줘야 한다.

세부 패턴이 필요하면 [제목 프레임워크](references/title-framework.md)를 읽는다. 기존 제목 비교나 최종 선정을 요청받으면 [평가 기준](references/evaluation-rubric.md)을 적용한다. 같은 주제의 좋은 예·나쁜 예가 필요하거나 패턴 선택이 어려우면 [사례집](references/examples.md)을 참고한다.

## 사실성과 증거

- `상위 노출`, `조회수 상승`, `홈판 선정`을 보장하지 않는다. `노출 가능성을 높이는 제목 후보`, `검색 의도 적합도가 높은 후보`처럼 표현한다.
- 타인 블로그의 공감·댓글·노출 위치를 정확한 조회수로 바꾸어 말하지 않는다. 정확한 게시글 조회수는 사용자 제공 통계나 접근 가능한 작성자 통계가 있을 때만 사용한다.
- 사용자가 실제 사례, 최신 알고리즘, 정책, 일정, 가격, 제도 조건을 요구하면 현재 자료를 확인한다. 네이버 공식 문서를 우선하고, 관찰 사례와 공식 사실을 구분한다.
- 웹 검증을 했다면 근거 링크와 확인 시점을 함께 제시한다. 검증할 수 없으면 미확인임을 밝힌다.

## 상세 분석 출력

```markdown
## 입력 진단
- 핵심 주제:
- 검색 의도:
- 독자가 결정하려는 것:
- 확인된 사실 / 확인 필요 정보:

## 검색형 제목
1. ...

## 홈판형 제목
1. ...

## 혼합형 제목
1. ...

## 최종 추천
- 검색 유입 우선:
- 홈판 클릭 우선:
- 균형형:

## 검수 메모
- 사실 확인이 필요한 표현:
- 본문에서 반드시 설명할 내용:
```

단축 호출에는 `단축 호출` 형식을 사용한다. 일반적인 간단한 요청에는 필요한 제목과 짧은 선정 이유만 제공한다. 분석을 요청받았을 때만 전체 진단을 출력한다.
