# 월별 추천과 계획

## 월만으로 시작하는 기본 흐름

사용자가 “이번 달 글 추천해줘” 또는 “3월에 쓸 주제 추천해줘”라고 하면 직접 키워드를 받지 않고 그 월의 후보를 조회한다. “글 추천”은 완성 글 작성과 구분한다. 분야·독자·개수 미지정은 전체 분야·일반 독자·8개로 시작하고, 기존 대화에서 확인한 블로그 성격이 있으면 반영한다. 월을 물어야 하는 요청이 아니라면 현재 월을 적용해 바로 추천한다.

연도·월·기준일을 결과 앞에 표시한다. 날짜 미지정 CLI는 실행 환경의 현재 날짜를 사용한다. 명시한 기준일과 대상 월은 서로 다를 수 있다. 예를 들어 10월에 12월 글을 기획할 때 확인 기준일은 현재, 대상 월은 12월이다. “다음 달”의 연도 변경은 에이전트가 계산해 year/month로 전달한다.

그달 추천 이유는 달력에 배치됐다는 말만으로 끝내지 않는다. 신청/신고 전 준비, 이용 중 문제 해결, 계절 생활 준비 등 독자의 현재 행동을 설명한다. 이미 끝난 마감은 신규 신청 안내 대신 조회·보완 등 남은 수요가 있는지 검토한다. 최신 공고가 필요하면 실제 읽고 확인 전 수치를 제목에 확정하지 않는다.

추천의 최종 번호와 topic_id를 함께 보존한다. “2번으로 써줘”는 그 선택을 그대로 이어 받아 article.py prepare와 실제 작성·검수·저장으로 진행한다. 기본 추천만 요청한 때는 원고와 drafted 이력을 만들지 않는다. 여러 달을 요청하면 월별로 나누고 같은 주제의 반복 배치 여부도 검토한다.

## 선택 기준

catalog.py recommend/plan은 해당 월·분야의 원문 관계 → 교정/사업명/행사명 검토 대기 제외 → 특정 연도·단기 공지 조건 → 동일 주제 그룹 한 개 → 블로그별 같은 회차 이력 순으로 거른다. 확정 편집 후보를 우선하고 주제군을 번갈아 배치해 한 분야의 표현만 목록을 채우지 않게 한다. 통계적 수요 순위가 아니다.

분야 별칭은 세금/직장인세금/연금, 지원/교육/복지, 여행, 건강, 생활, 생활정보다. 생활정보는 생활·기념일과 건강·안전을 함께 포함한다. 정확한 분류명도 사용 가능하며 생략하면 전체다. 여행에 행사명이 없는 범용 축제 문구가 많아 요청 수보다 후보가 적을 수 있다. 빈자리를 억지로 채우지 않는다.

기본 요청 수는 8개다. 사용자가 정한 수를 우선하고, 최종 의미 검토로 겹치는 후보를 제외하면 필요할 때 더 넓은 원시 후보를 조회한다. 같은 질문의 환급 입금일/지급시간 표현 등은 하나로 묶되 지급시간을 사실처럼 약속하지 않는다. 신규 신청과 누락 서류 보완처럼 독자의 행동이 다른 글은 구분한다. 다중 월 문구는 하나의 키워드 ID에 원문 월을 모두 보존한다.

최종 목록마다 **주제·대표 키워드·가제·독자의 질문·추천 이유·작성 시점 제안·확인할 핵심 사실**을 제공한다. 작성 시점 제안과 공고의 실제 마감일을 구분한다. 확인 전 가제의 금액·날짜를 확정하지 않는다. 원시 JSON의 facts_status=unverified와 semantic_review_required=true는 최종 사실 확인/의미 검토 전 상태다.

## 이력 반영

workspace/blog를 지정하면 해당 블로그 이력을 읽는다. recommended는 후보를 소진하지 않는다. selected/drafted/published는 같은 회차 신규에서 제외한다. needs_update는 신규와 분리된 updates에 나타난다. 이력 없는 추천은 그 사실을 밝히고 장기 중복 방지라고 보고하지 않는다. 다른 작업 공간·블로그·외부 네이버 글은 자동 조회하지 않는다.

이미 작성한 글에 대해 사용자가 갱신을 요청하면 이전 추천 패킷으로 update brief를 만들 수 있다. 또는 history.py record로 needs_update와 실제 reason을 먼저 저장한 뒤 재추천한다. 취소한 selected는 동일 ID로 임의 되돌리지 않는다. 현재 버전에서는 취소 전이를 제공하지 않으므로 기록 전에 선택이 확정됐는지 판단하며, 단순 추천 단계는 기록하지 않아도 된다.

## 회차와 계획

연말정산은 1~2월에 이전 귀속연도, 그 외에는 현재 귀속연도로 추정한다. 종합소득세는 이전 소득연도, 반기 장려금은 상반기 요청에 이전 연도 하반기/하반기 요청에 현재 연도 상반기를 추정한다. 학기·차수·월별 납부·연간·상시 글은 data-contract의 구분을 따른다. 원문만으로 대상이 확정되지 않으면 공식 자료를 보고 `--period`에 ASCII 회차명(예: `income-2026-H1`, `academic-2027-S1-R2`)을 넣어 동일 회차를 일관되게 사용한다. period는 단순 중복 회피용으로 바꾸지 않는다.

plan은 작성 순서 sequence를 추가한다. 자동 발행 날짜·캘린더 등록·예약을 만들지 않는다. 사용자 요청 시 월간 표로 정리하되 공식 일정이 불명확하면 ‘일정 확인 후’라고 표시한다.

## 요청 예

```text
$naver-seasonal-blog-writer 이번 달에 필요한 블로그 주제를 추천해줘.
$naver-seasonal-blog-writer 3월에 쓸 글감을 추천해줘.
$naver-seasonal-blog-writer 다음 달 생활정보 주제 5개 추천해줘.
$naver-seasonal-blog-writer 방금 추천한 2번 주제로 블로그 글을 작성해줘.
$naver-seasonal-blog-writer 11월 생활정보 글감 8개를 추천해줘. 글은 아직 쓰지 마.
$naver-seasonal-blog-writer 내 블로그 worklife의 12월 세금 글감을 기존 원고와 겹치지 않게 계획해줘.
$naver-seasonal-blog-writer 추천한 수도관 동파 예방 주제로 한 편 작성하고 이력에 남겨줘.
$naver-seasonal-blog-writer 지난 동파 예방 글에 외출 전 체크리스트를 보완해 새 버전으로 저장해줘.
$naver-seasonal-blog-writer worklife 블로그의 작성 이력을 보여줘.
```
