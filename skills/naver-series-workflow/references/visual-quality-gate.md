# 완성형 원고 시각 품질 게이트

## 목차

- 수량과 역할
- 스타일별 목표
- 파일·슬롯 검사
- 시각 QA
- 실패 상태

## 수량과 역할

`naver-series/v2`의 이미지 포함 완성형은 회차마다 승인된 고유 이미지 최소 3장을 요구한다.

1. `cover` 1장: H1 바로 아래 첫 콘텐츠 블록에 두고 글의 핵심 상황을 보여준다.
2. `inline` 2장 이상: 원리·비교·절차·진단·요약 중 서로 다른 정보 역할을 맡는다.

3장은 검색 노출 공식이 아니라 표지만 있는 불완전한 패키지를 완료로 처리하지 않기 위한 제작 하한이다. 이미지 미요청의 `optional`과 명시적 텍스트 전용 `none`에는 이 하한을 적용하지 않는다.

## 스타일별 목표

| primary | 기본 목표 | 권장 비트 |
|---|---:|---|
| `expert` | 5 | 대표, 메커니즘, 계산·과정, 비교·진단, 요약 |
| `story` | 4 | 시작, 문제·시도, 전환점, 해결·교훈 |
| `review` | 5 | 실제 대표, 환경, 과정, 장단점 근거, 판단 |
| `friendly` | 3 | 대표, 쉬운 개념, 따라 하기 |
| `troubleshooting` | 4 | 증상, 원인, 정상/비정상, 조치 |
| `comparison` | 4 | 대표, 구조 차이, 기준 비교, 선택 |

최소 수량 충족과 목표 수량 충족은 별도 상태로 보고한다. 생성 단계에서는 목표를 우선하지만, 최소 3장과 역할 조건을 모두 통과하면 `visual_minimum_met=true`가 될 수 있다.

## 파일·슬롯 검사

- `approved` 슬롯과 디코딩 가능한 PNG/JPEG만 센다.
- 파일 내용 SHA-256이 같으면 이름과 경로가 달라도 한 장으로 센다.
- slot 순서는 article marker 순서와 같아야 한다.
- 첫 slot은 `cover`이고 전체 cover는 정확히 하나여야 한다.
- cover slot과 결합된 canonical image block은 H1을 제외한 첫 콘텐츠 block이어야 한다. 빈 줄은 무시하지만 도입 문단·소제목·다른 이미지를 먼저 둘 수 없다.
- inline은 두 개 이상이어야 한다.
- 한 이미지가 두 개의 서로 다른 정보 역할을 대신한다고 기록하지 않는다.
- alt는 독자가 놓칠 정보를 설명하고 caption은 인접 문단과의 관계를 설명한다.
- 실제 UI·공식 문서·체험 증거가 필요하면 사용자 제공 또는 공식 원본을 사용한다.

## 시각 QA

| 항목 | 통과 기준 |
|---|---|
| 관련성 | 인접 문단의 원리·상황·판단을 실제로 보완 |
| 사실성 | 본문의 수치·대상·관계를 왜곡하지 않음 |
| 식별 오류 | 손, 얼굴, 기구, 글자에 명백한 생성 오류가 없음 |
| 브랜드 | 허위 로고·공식 UI·공문처럼 보이는 요소가 없음 |
| 스타일 | 한 회차 안에서 팔레트·현실성·인물 설정이 일관됨 |
| 모바일 crop | 좁은 화면에서도 핵심 피사체와 관계가 유지됨 |
| 경험 경계 | 생성 장면이 실제 구매·사용·방문 증거로 제시되지 않음 |

시각 QA는 파일 존재 검사로 대체할 수 없다. 실제로 보지 않은 이미지는 `image_relevance`를 passed로 기록하지 않는다.

## 실패 상태

| 오류 코드 | 의미 |
|---|---|
| `VISUAL_MINIMUM_NOT_MET` | 승인된 고유 이미지가 최소 수량보다 적음 |
| `INLINE_IMAGES_MISSING` | cover 1장+inline 2장 역할 계약 불충족 |
| `COVER_POSITION_INVALID` | cover 역할은 맞지만 canonical post의 첫 콘텐츠 block에 배치되지 않음 |
| `DUPLICATE_ASSET` | 다른 슬롯에서 동일 이미지 바이트 재사용 |
| `ASSETS_PENDING` | 슬롯·파일·승인·디코딩 문제로 합성 불가 |

위 오류가 있으면 SmartEditor 입력 단계로 넘어가지 않는다. 이미지 수정은 새 content revision과 새 검수를 요구한다.
