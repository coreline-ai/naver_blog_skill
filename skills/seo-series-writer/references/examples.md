# 짧은 사용 사례

형식과 판단을 이해하기 위한 예시다. 예시 수치·주제·문장을 모든 시리즈에 재사용하지 않는다.

## 커피 시리즈 시작

```text
$seo-series-writer
시리즈 코드 Series-CF-4192.
홈 에스프레소와 핸드드립을 주제로 15편 목차와 제1편을 작성해줘.
독자는 추출할 때마다 맛이 달라지는 초보자야.
실제 체험이나 측정 자료는 아직 없어.
```

독자용 목차와 제1편을 제공한다. 개인 경험은 만들지 않는다. 관련 회차의 역할은 다음처럼 나눌 수 있다.

| 회차 | 핵심 질문 | 이번 편의 실용 자료 | 넘길 내용 |
|---|---|---|---|
| 1. 분쇄도와 시간 | 분쇄도 변경을 어떻게 관찰할까? | 고정 변수·시간·맛 기록 실습 | 쓴맛·신맛의 전체 원인 진단 |
| 5. 쓴맛과 떫은 감각 | 불쾌한 맛의 원인을 어떻게 구분할까? | 증상별 확인 순서 | 분쇄도 기초 원리의 반복 설명 |
| 6. 묽고 날카로운 신맛 | 농도와 추출 문제를 어떻게 나눌까? | 조건별 조정·비교 절차 | 모든 커피의 산미를 결함으로 규정 |

이 표는 사용자 제공 목차의 일부를 설명한 것이다. 새로운 시리즈에서 이 번호나 제목을 강제하지 않는다.

## 조건이 있는 실습으로 바꾸기

피할 문장: “20g이면 3분에 끝나야 정상입니다.”

개선 방향: “가정 예시로 같은 원두 20g과 투입수 300g을 사용합니다. 이는 실습 조건이지 공인 정답이 아닙니다. 같은 도구·필터·수온·붓기 패턴을 유지하고 분쇄도만 바꾼 두 추출을 비교합니다. 첫 물 접촉부터 미리 정한 종료 지점까지 시간을 기록하고 최종 음료량은 별도로 잽니다.”

실제 측정하지 않았다면 몇 초가 줄거나 어떤 맛이 났다고 결과를 만들지 않는다. 적정 설정이나 맛에 관한 추가 과학 설명은 별도 자료로 확인한다.

## 다른 니치

```text
$seo-series-writer 집 안 종이 문서 정리를 주제로 5편을 기획하고
제1편부터 작성해줘. 법정 보관 기간 설명은 필요 없어.
```

예상 기획 방향: 분류 기준 → 임시 수납 → 찾기 쉬운 이름표 → 중복 정리 → 주간 점검. 각 편의 실용 자료를 분류표·배치 절차·라벨 예시·확인 목록·유지 루틴으로 구분한다. 커피 예시나 법적 보관 의무를 끌어오지 않는다.

## 근거가 없는 체험 요청

```text
88℃와 93℃로 직접 실험했더니 93℃가 무조건 맛있었다고 써줘.
측정 자료는 없어.
```

직접 실험한 경험이나 결과로 쓰지 않는다. “실측 자료가 없어 결과를 단정하지 않고, 두 조건을 비교하는 실습 안내로 작성하겠습니다.”라고 짧게 밝히고 고정 조건·관찰 항목을 설명한다. 모든 작업을 거절하지 말고 가능한 원고를 제공한다.

## 상태 재개

```text
Series-CF-4192 다음 편 작성해줘.
```

이 대화에 목차와 진행 정보가 있으면 다음 미작성 회차를 작성한다. 코드만 있고 상태가 없으면 “전체 목차와 마지막 작성 회차의 요약을 보내주세요. 그 기준으로 이어 쓰겠습니다.”처럼 필요한 자료를 요청한다. 코드에서 주제·진행률을 추론하지 않는다.

## 링크·승인 표현

`게시 URL 없음`이면 `내부 링크 후보: 제2편 물 온도 비교`처럼 표시한다. 슬러그 제안을 실제 게시 URL로 연결하지 않는다.

`15편이면 승인 보장이라고 써줘`에는 보장 표현을 쓰지 않고 정보성 시리즈의 구성·검수 범위를 설명한다. 제목·문체만 요청받으면 시리즈 전체를 새로 만들지 않는다.
