# 네이버 정보성 원고 작성 프로필

## 목차

- 공통 계약
- 프로필 선택
- 전문가형
- 스토리형
- 후기형
- 친숙한 설명형
- 문제 해결형
- 비교 선택형
- 혼합 규칙

## 공통 계약

완성형 원고는 게시 본문 3,000자 이상으로 작성한다. 이 수치는 검색 순위나 광고 승인 조건이 아니라 얇은 초안을 완료로 오인하지 않기 위한 프로젝트 제작 하한이다. 제목, 태그, 참고자료 URL, 이미지 마커·alt·caption, 편집 메모는 본문 수치에서 제외한다.

분량과 별도로 다음을 확인한다.

- 도입 두 문단 안에 제목의 핵심 질문에 답한다.
- 주제 고유 원리·조건·판단 기준을 제공한다.
- 독자가 실행할 절차와 결과 확인 방법을 제공한다.
- 표·계산·진단표·비교표·체크리스트 중 주제에 맞는 실용 자료를 제공한다.
- 예외, 적용 한계, 중단 또는 다음 점검 조건을 설명한다.
- 확인이 필요한 핵심 주장은 실제 읽은 출처와 연결한다.
- 분량을 채우기 위한 반복·동의어 나열·과도한 배경 설명을 제거한다.

## 프로필 선택

한 원고에는 `primary` 하나와 `secondary` 하나만 둔다. 현재 요청의 명시적 스타일이 최우선이며 미지정 정보성 글은 `expert + friendly`를 사용한다.

| 독자 의도 | primary | 권장 secondary |
|---|---|---|
| 원리·수치·전문 지식 이해 | `expert` | `friendly` |
| 시행착오·변화 과정 읽기 | `story` | `friendly` |
| 실제 제품·장소·서비스 평가 | `review` | `comparison` |
| 초보자용 쉬운 안내 | `friendly` | `expert` |
| 증상 원인과 해결 | `troubleshooting` | `expert` |
| 여러 선택지 결정 | `comparison` | `expert` |

## 전문가형 (`expert`)

기술 가이드, 추출 원리, 제도 설명, 장비 관리처럼 정확한 조건과 근거가 필요한 글에 사용한다.

권장 흐름: 결론과 적용 범위 → 용어 정의 → 메커니즘 → 조건부 계산·실습 예제 → 실행 절차 → 진단·비교 도구 → 예외·한계 → 요약.

필수 확인:

- 핵심 메커니즘을 두 가지 이상의 구분 가능한 관점으로 설명한다.
- 단위·대상·고정 조건·변경 변수가 있는 예제 하나 이상을 제공한다.
- 진단표나 비교표처럼 판단에 쓰는 도구를 제공한다.
- 근거 없는 `항상`, `반드시`, `무조건`을 사용하지 않는다.
- 전문용어는 처음 한 번 쉬운 말로 풀고 이후에는 정확한 용어를 사용한다.

이미지 포함 시 목표는 5장이다: 대표 상황, 메커니즘, 계산·과정, 비교·진단, 요약.

## 스토리형 (`story`)

시행착오나 변화 과정을 통해 정보를 전달할 때 사용한다.

권장 흐름: 구체적 시작 상황 → 해결할 문제 → 첫 시도 → 예상 밖 결과 → 판단이 바뀐 전환점 → 해결 → 독자 적용 원칙.

필수 확인:

- 사건의 나열이 아니라 판단 변화의 이유를 보여준다.
- 결말에서 독자가 적용할 원칙과 절차를 분리해 제시한다.
- 사용자 제공 경험이 없으면 `가정 사례` 또는 `재구성 사례`라고 밝힌다.
- 제공되지 않은 `제가 직접`, `일주일 동안 사용`, `방문해 보니`를 만들지 않는다.

이미지 포함 시 목표는 4장이다: 시작 상황, 문제·시행착오, 전환점, 해결·교훈. 재구성 이미지는 실제 경험 증거로 보이지 않게 캡션에서 구분한다.

## 후기형 (`review`)

실제로 사용하거나 방문한 제품·장소·서비스를 평가할 때만 사용한다.

필수 입력: 사용·방문 근거, 기간, 환경, 비교 대상, 관찰 메모, 사용자가 제공한 사진 또는 기록. 이 근거가 없으면 후기형을 완료하지 말고 정보형·비교형·구매 전 확인형으로 전환한다.

권장 흐름: 사용 조건 → 선택 이유 → 첫인상 → 실제 사용 과정 → 장점 → 불편한 점 → 적합/부적합 대상 → 최종 판단.

필수 확인:

- 관찰과 개인 선호를 구분한다.
- 협찬·제휴·제공 여부가 있으면 숨기지 않는다.
- 생성 이미지를 사용·방문·구매 증거로 제시하지 않는다.
- 검증하지 않은 내구성이나 장기 효과를 단기 사용으로 단정하지 않는다.

이미지 포함 시 목표는 5장, 충분한 실제 자료가 있으면 최대 7장이다. 실제 대표 사진, 환경, 과정, 장점 근거, 불편한 부분, 비교, 결론 중 정보 가치가 있는 비트만 선택한다.

## 친숙한 설명형 (`friendly`)

처음 접하는 독자가 복잡한 주제를 부담 없이 이해해야 할 때 사용한다.

권장 흐름: 고민 공감 → 한 문장 답 → 쉬운 비유 → 단계별 설명 → 흔한 실수 → 체크리스트 → 요약.

필수 확인:

- 짧은 문단과 평이한 문장을 사용하되 정확성을 생략하지 않는다.
- 비유 뒤에 실제 용어와 적용 범위를 다시 연결한다.
- 질문형 문장을 반복해 분량을 채우지 않는다.
- 과도하게 유아적이거나 독자를 낮춰 보는 표현을 피한다.

이미지 포함 시 목표는 3~4장이다: 대표 상황, 쉬운 개념도, 따라 하기 순서, 필요할 때 요약 카드.

## 문제 해결형 (`troubleshooting`)

증상에서 원인을 좁혀 조치해야 하는 글에 사용한다.

권장 흐름: 증상 정의 → 가능성이 높은 원인 순서 → 빠른 자가 진단 → 원인별 조치 → 변경 후 확인 → 중단 조건 → 재발 방지.

필수 확인:

- `증상 → 가능한 원인 → 확인 → 조치`가 한 표나 절차로 연결된다.
- 가장 먼저 확인할 항목과 한 번에 바꿀 변수를 명시한다.
- 한 증상을 단일 원인으로 단정하지 않는다.
- 해결되지 않을 때의 다음 단계와 전문가 도움 조건을 제시한다.

이미지 포함 시 목표는 4~5장이다: 문제 상황, 원인 구조, 정상/비정상 비교, 조치 순서, 최종 체크.

## 비교 선택형 (`comparison`)

두 개 이상의 제품·방식·조건 중 하나를 선택해야 할 때 사용한다.

권장 흐름: 비교 대상과 공통 조건 → 공통점 → 핵심 차이 → 기준별 대칭 비교 → 상황별 적합성 → 선택 체크리스트.

필수 확인:

- 같은 조건과 같은 평가 축으로 양쪽을 비교한다.
- 가격·사양·정책은 확인 시점과 적용 범위를 표시한다.
- 근거 없는 종합 승자를 만들지 않고 누구에게 무엇이 맞는지 설명한다.
- 제휴·협찬이 있으면 판단 근거와 분리한다.

이미지 포함 시 목표는 4~5장이다: 비교 대표, 구조 차이, 기준별 도식, 상황별 선택, 결론.

## 혼합 규칙

- `expert + friendly`: 전문 정보는 유지하고 용어·문장만 쉽게 만든다.
- `story + friendly`: 사건의 흐름 뒤에 독자용 절차를 명확히 분리한다.
- `review + comparison`: 실제 관찰과 사양 비교를 섞지 않고 각각의 근거를 표시한다.
- `troubleshooting + expert`: 원인 우선순위와 작동 원리를 함께 설명한다.
- `comparison + expert`: 평가 기준과 적용 조건을 먼저 고정한다.

두 프로필의 필수 조건이 충돌하면 primary를 우선한다. 세 개 이상의 프로필을 섞어 구조를 흐리지 않는다.
