# 시리즈 기획과 이어쓰기

## 입력 기본값

| 항목 | 미지정 시 | 명시된 입력이 있을 때 |
|---|---|---|
| 니치 | 장기적으로 유용한 세부 분야 하나를 선정 | 사용자 주제를 유지 |
| 독자 | 초보~초중급 | 독자 수준·목적 우선 |
| 편수 | 15편 | 양의 정수인 요청 편수 우선; 목차만 주어졌다면 그 항목 수 사용 |
| 이번 범위 | 전체 목차 + 제1편 | 목차만·특정 회차·범위를 우선 |
| 문체 | 친절한 설명형 존댓말 | 제공된 문체 반영; 개인 경험은 별도 사실 자료로 판단 |
| 형식 | Markdown | 명시적 다른 형식은 가능 범위에서 반영 |
| 분량 | 편당 약 2,000~3,000자를 편집 출발점으로 사용 | 사용자 분량과 질문 해결 우선; 반복으로 글자 수를 채우지 않음 |
| 코드 | `Series-<주제 약자>-<숫자>` 형태의 관리용 표식 | 제공된 코드 그대로 유지 |
| 발행 패키지 | 생략 | 요청 시 본문과 분리 |

닉네임은 선택 사항이다. 닉네임·기기·세부 관심 분야가 없다는 이유만으로 시작을 막지 않는다. 다만 편수와 목차 수가 충돌하거나 회차가 범위를 벗어나면 한 번의 짧은 질문으로 모호성을 해소한다. 코드의 전역 유일성·원격 등록·영구 기억을 주장하지 않는다.

## 니치와 목차

1. 주제 미지정 시 특정 독자에게 유용하고, 검증 자료를 찾을 수 있으며, 요청 편수만큼 다른 질문으로 확장할 수 있는 니치를 고른다. 실용 가이드가 가능한 주제를 우선하되 커피를 고정 기본값으로 쓰지 않는다.
2. 선정 이유는 독자의 문제와 콘텐츠 확장성으로 설명한다. 조사하지 않은 검색량·경쟁 강도·승인 가능성을 이유로 제시하지 않는다.
3. 목차를 대체로 기초 → 변수 → 문제 해결 → 응용·비교 → 관리·기록 흐름으로 설계한다. 주제와 제공된 목차에 맞게 순서를 조정한다.
4. 각 편에 아래 기획 항목을 배정하여 제목만 다른 중복 글을 막는다. 원고 작성 전에 관련 회차와 경계를 대조한다.

| 회차 기획 항목 | 내용 |
|---|---|
| 번호·제목 | 안정적인 회차 번호와 독자에게 약속할 답 |
| 핵심 질문 | 이번 편 하나로 해결할 질문 1개 |
| 검색어 후보 | 메인 1개·보조 2~4개; 실제 검색량 자료와 구분 |
| 포함 범위 | 이번 편에서 설명·판단할 항목 |
| 제외 범위 | 다른 회차로 넘길 상세 항목 |
| 고유 실용 자료 | 점검 절차·비교 기준·실습·계산·기록 양식 중 필요한 것 |

이 기획표를 매 응답에 출력하지 않는다. 첫 응답에는 독자용 제목 목차를, 기획 상세나 상태 요약 요청에는 필요한 정보를 공개한다. 각 글은 단독으로도 핵심 질문에 답해야 하며, 다른 편으로 넘기는 링크가 답변의 대체재가 되어서는 안 된다.

사용자 목차는 유지한다. 사실과 어긋나거나 결과를 보장하는 제목만 취지를 유지해 최소 수정하고 편집 메모에 원래 제목과 이유를 밝힌다. 임의로 회차를 합치거나 전체 주제를 교체하지 않는다.

## 작성 범위 판정

| 요청 | 수행 |
|---|---|
| 새 시리즈 | 목차를 정하고 제1편 작성. `목차만` 요청이면 본문 생략 |
| 다음 편 | 확정된 목차 안에서 작성되지 않은 가장 작은 번호를 선택 |
| 제N편 | 해당 회차만 작성; 다른 회차를 완료로 간주하지 않음 |
| 제N편 재작성 | 해당 원고와 요약만 갱신; 완료 회차 중복 집계 금지 |
| 제N~M편 | 요청한 범위를 순서대로 작성 |
| 발행 패키지 | 확인 가능한 대상 원고에 대한 메타데이터만 작성 |
| 상태 요약 | 아래 휴대용 상태를 출력; 새 글을 추가로 생성하지 않음 |

긴 범위는 출력 가능한 분량 안에서 **완성된 회차 단위**로 제공한다. 전체를 짧은 요약으로 바꾸거나 작성하지 않은 회차까지 완료했다고 하지 않는다. 응답 끝에 실제 완료·남은 범위를 알리고, 다음 사용자 요청에서 이어간다. 사용자 응답 없이 후속 생성·예약 게시가 계속된다고 약속하지 않는다.

1편짜리 시리즈와 마지막 편은 다음 편 예고 대신 활용법으로 마무리한다. 모두 작성된 상태에서 `다음`을 요청받으면 완료 사실과 가능한 수정·보완을 짧게 안내하며 제16편을 임의로 만들지 않는다.

## 휴대용 상태

대화에서 확인 가능한 원고·목차·상태 요약을 사용한다. 단순히 마지막 출력 번호에 1을 더하지 않는다. 예를 들어 작성 완료가 `[1, 3]`이면 다음은 `2`다.

상태 요청이나 다른 대화로 이동할 때 다음 형식으로 내보낸다. 사용자가 파일을 요청하지 않았다면 텍스트로 제공하며 스킬 폴더에 저장하지 않는다.

```text
[시리즈 상태 v1]
코드: …
니치 / 독자 / 문체: …
전체 편수: …
확정 목차:
- 1. 제목 | 질문: … | 포함: … | 제외: … | 실용 자료: …
- (전체 목차를 빠짐없이 나열)
작성 완료 회차: […]
검토 대기 회차: […]
완료 요약:
- N: 다룬 핵심 / 사용한 예시·조건 / 다음 편에서 반복하지 않을 내용
확인 자료와 미확인 사항:
- N: 실제 확인 출처·확인 시점 또는 사용자 자료 / 확인하지 못한 핵심 주장
게시 URL: 사용자 제공 URL 또는 없음
다음 회차: 가장 작은 미작성 번호 또는 완료
```

- `작성 완료`는 완성된 초안을 사용자에게 제공했다는 뜻이다. 게시·승인·사실 검증 완료가 아니다. 원고 전체를 제공했지만 검증이 남았다면 작성 완료와 검토 대기에 모두 넣는다.
- 개요만 제공하거나 문장이 중간에 끊긴 회차는 작성 완료에 넣지 않는다.
- 재작성 시 완료 목록은 집합처럼 유지하고 요약과 검토 상태만 갱신한다.
- 코드만으로 이전 대화를 조회할 수 있다고 말하지 않는다. 목차·진행 상태를 확인할 수 없으면 전체 목차와 완료 요약을 요청한다.
- 불완전한 상태에서 빠진 원고 내용·측정값·출처를 추측하지 않는다. 관련 회차의 요약 또는 원고만 추가로 요청한다.
- 가져온 상태가 서로 모순되면 필요한 항목만 확인한다. 새 니치로 시작하라는 명시적 요청이 아니라면 기존 시리즈를 임의로 초기화하지 않는다.

평소에는 전체 상태를 반복하지 말고 본문 뒤 편집 메모에 `작성 완료 1/15 · 다음 제2편 · 검토 대기 없음/해당 항목` 정도만 표시한다.
