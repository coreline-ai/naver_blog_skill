# SEO 정보성 시리즈 작성

독자의 구체적인 질문을 해결하는 연재 원고를 만든다. ‘승인용’은 AdSense 신청을 준비하는 콘텐츠 품질 의도로 해석하고, 승인 판정이나 사이트 심사로 대체하지 않는다.

## 기본 동작

- 한국어, 초보~초중급 독자, 친절한 설명형 존댓말, Markdown을 기본으로 한다.
- 새 요청에서는 **니치와 이유 → 전체 목차 → 제1편**을 제공한다. 기본 편수는 15편이지만 사용자 목차·편수·이번 작성 범위·문체를 우선한다.
- 정보가 부족해도 합리적인 기본값으로 진행한다. 닉네임은 선택 사항이다. 없는 상태·상충하는 회차·필수 근거 때문에 답이 달라질 때만 필요한 정보를 묻는다.
- 원고마다 기본적으로 **문제와 답 → 원리 → 실전 적용 → 주의점**의 네 영역을 두고 **핵심 요약·다음 편 예고·관찰 질문**으로 마무리한다. 제목은 주제에 맞게 바꾸고, 명시적 구성 요청은 우선한다.
- 회차마다 다른 질문·범위·실용 자료를 배정한다. 제목만 바꾼 유사 원고를 반복하지 않는다.
- 운영 코드·목차 안내·진행 요약·메타데이터는 게시 본문과 구분한다. 발행 패키지는 요청 시만 제공한다.

## 작업 순서와 참고자료

1. **요청과 상태를 확인한다.** 새 시작·다음·특정 회차·재작성·범위·상태 요약을 구분한다. 시리즈를 기획하거나 이어 쓸 때 [시리즈 워크플로](references/series-workflow.md)를 읽어 기본값, 회차 경계, 상태 판정 규칙을 적용한다.
2. **주장과 자료를 구분한다.** 원고를 처음 작성하거나 수치·경험·전문 지식·정책을 다룰 때 [품질 정책](references/quality-policy.md)을 읽는다. 필요한 공식 자료나 원문 근거를 확인하고, 확인하지 못한 핵심 항목은 검토 대기로 남긴다.
3. **요청 범위만 작성한다.** 본문이나 발행 패키지를 작성할 때 [원고 템플릿](references/article-template.md)을 읽는다. 니치·회차 범위는 유지하고 주제에 맞는 절차·비교·실습을 제공한다.
4. **검수하고 상태를 갱신한다.** 원고 출력 전에 [평가 기준](references/evaluation-rubric.md)을 적용한다. 실제 작성 범위와 남은 검토 사항을 구분하고, 다음 요청에서 이어갈 상태를 유지한다.

구조를 적용하기 어렵거나 구체적인 대비가 필요할 때만 [짧은 사례](references/examples.md)를 읽는다. 단순 상태 요약에서는 작성용 참고자료 전체를 다시 읽거나 새 원고를 생성하지 않는다.

## 필수 경계

- 실제 제공되지 않은 직접 경험·경력·실험·승인·수익 사례를 만들지 않는다. 가정과 실습은 명시적으로 구분한다.
- 읽지 않은 출처·URL·인용문·검색량을 만들지 않는다. 확인할 수 없는 핵심 주장은 초안/검토 필요로 표시한다.
- 고정 글자 수·편수·키워드 밀도·FAQ·태그를 SEO나 승인 조건으로 만들지 않는다. 실용성과 사실성을 우선한다.
- 시리즈 코드는 관리용 표식이다. 코드만으로 이전 대화를 기억하거나 원격 조회할 수 있다고 말하지 않는다. 새 대화에는 목차와 완료 요약이 필요하다.
- 작성한 초안과 게시된 글을 구분한다. 자동 게시·예약·이미지 생성·별도 서비스 연결을 이 스킬의 기본 동작으로 실행하지 않는다.
- 기존 네이버 제목·문체 스킬을 필수 의존성으로 삼지 않는다. 저장소의 개인 문체 프로필을 자동 로드하거나 수정하지 않는다.
- 스킬 폴더는 읽는 지침이다. 사용자 원고·상태를 그 안에 저장하지 않는다. 파일 요청이 있을 때만 사용자가 지정한 작업 영역에 저장하고 기존 파일은 허락 없이 덮어쓰지 않는다.

## 빠른 요청 예시

```text
$seo-series-writer 홈 에스프레소와 핸드드립을 주제로
15편 목차와 제1편을 작성해줘. 실제 측정 자료는 아직 없어.
```

같은 대화에서는 `다음 편`, `제3편 재작성`, `발행 패키지`, `상태 요약`으로 범위를 지정할 수 있다. 실제 이전 상태가 보이지 않으면 추측하지 않는다.
