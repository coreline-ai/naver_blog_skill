# SEO 정보성 시리즈 작성

독자의 구체적인 질문을 해결하는 연재 원고를 만든다. ‘승인용’은 AdSense 신청을 준비하는 콘텐츠 품질 의도로 해석하고, 승인 판정이나 사이트 심사로 대체하지 않는다.

## 기본 동작

- 한국어, 초보~초중급 독자, 친절한 설명형 존댓말, Markdown을 기본으로 한다.
- 새 요청에서는 **니치와 이유 → 전체 목차 → 제1편**을 제공한다. 기본 편수는 15편이지만 사용자 목차·편수·이번 작성 범위·문체를 우선한다.
- 완성형 원고의 게시 본문은 최소 3,000자로 작성한다. 제목·태그·참고자료 URL·이미지 마커/alt/caption·편집 메모는 세지 않는다. 이 하한은 검색 또는 승인 공식이 아니라 얇은 초안을 완료로 오인하지 않기 위한 제작 기준이다. 사용자가 짧은 요약·개요만 요청하면 그 범위를 따르되 완성형이라고 표시하지 않는다.
- 작성 전에 [작성 프로필](references/writing-profiles.md)에서 primary 하나와 secondary 하나를 선택한다. 명시적 요청이 없으면 `expert + friendly`로 한다. 프로필은 말투뿐 아니라 글의 구조·필수 실용 자료·근거 수준을 결정한다.
- 정보가 부족해도 합리적인 기본값으로 진행한다. 닉네임은 선택 사항이다. 없는 상태·상충하는 회차·필수 근거 때문에 답이 달라질 때만 필요한 정보를 묻는다.
- 원고마다 기본적으로 **문제와 답 → 원리 → 실전 적용 → 주의점**의 네 영역을 두고 **핵심 요약·다음 편 예고·관찰 질문**으로 마무리한다. 제목은 주제에 맞게 바꾸고, 명시적 구성 요청은 우선한다.
- 회차마다 다른 질문·범위·실용 자료를 배정한다. 제목만 바꾼 유사 원고를 반복하지 않는다.
- 초안은 주제 고유성을 확인한다. 장소명·제품명·증상명만 다른 말로 바꿔도 대부분 유지되는 문장은 보강 대상으로 본다. 여행 글에는 실제 권역·동선 선택 예시를, 문제 해결 글에는 증상→판단→조치→중단 조건을 넣는 등 독자가 실행할 구체적 자료를 제공한다.
- 운영 코드·목차 안내·진행 요약·메타데이터는 게시 본문과 구분한다. 발행 패키지는 요청 시만 제공한다.

## 작업 순서와 참고자료

1. **요청과 상태를 확인한다.** 새 시작·다음·특정 회차·재작성·범위·상태 요약을 구분한다. 시리즈를 기획하거나 이어 쓸 때 [시리즈 워크플로](references/series-workflow.md)를 읽어 기본값, 회차 경계, 상태 판정 규칙을 적용한다.
2. **프로필을 고른다.** 완성형 본문이면 [작성 프로필](references/writing-profiles.md)을 읽고 요청의 검색 의도와 경험 근거에 맞춰 primary/secondary를 정한다. 후기형은 실제 사용·방문 근거가 없으면 정보형 또는 비교형으로 바꾸고 변경 이유를 편집 메모에 남긴다.
3. **주장과 자료를 구분한다.** 원고를 처음 작성하거나 수치·경험·전문 지식·정책을 다룰 때 [품질 정책](references/quality-policy.md)을 읽는다. 필요한 공식 자료나 원문 근거를 확인하고, 확인하지 못한 핵심 항목은 검토 대기로 남긴다.
4. **요청 범위만 작성한다.** 본문이나 발행 패키지를 작성할 때 [원고 템플릿](references/article-template.md)을 읽는다. 니치·회차 범위는 유지하고 선택 프로필에 맞는 절차·비교·실습을 제공한다.
5. **분량과 의미를 따로 검수한다.** 완성형 본문은 공개 텍스트 기준 3,000자 이상인지 확인한다. 이어서 [평가 기준](references/evaluation-rubric.md)의 직접 답, 주제 고유 사실, 실용 자료, 예외, 출처, 회차 차별성을 실제 위치로 확인한다. 길이만 충족한 원고를 완료로 표시하지 않는다.
6. **상태를 갱신한다.** 실제 작성 범위와 남은 검토 사항을 구분하고 다음 요청에서 이어갈 상태를 유지한다. 이미지가 요청되면 안정된 원고와 사실 검수 뒤에 시각 비트를 넘기며, 이미지 완료 전 SmartEditor 입력을 준비 완료로 표시하지 않는다.

구조를 적용하기 어렵거나 구체적인 대비가 필요할 때만 [짧은 사례](references/examples.md)를 읽는다. 단순 상태 요약에서는 작성용 참고자료 전체를 다시 읽거나 새 원고를 생성하지 않는다.

## 필수 경계

- 실제 제공되지 않은 직접 경험·경력·실험·승인·수익 사례를 만들지 않는다. 가정과 실습은 명시적으로 구분한다.
- 읽지 않은 출처·URL·인용문·검색량을 만들지 않는다. 확인할 수 없는 핵심 주장은 초안/검토 필요로 표시한다.
- 고정 글자 수·편수·키워드 밀도·FAQ·태그를 SEO나 승인 조건으로 만들지 않는다. 실용성과 사실성을 우선한다.
- `3,000자`를 이 스킬의 완성형 제작 하한으로 적용하되, 검색 노출·승인 조건이나 충분조건으로 설명하지 않는다. 반복 문장·동의어 나열·무관한 배경으로 채운 원고는 분량과 관계없이 수정한다.
- 시리즈 코드는 관리용 표식이다. 코드만으로 이전 대화를 기억하거나 원격 조회할 수 있다고 말하지 않는다. 새 대화에는 목차와 완료 요약이 필요하다.
- 작성한 초안과 게시된 글을 구분한다. 자동 게시·예약·이미지 생성·별도 서비스 연결을 이 스킬의 기본 동작으로 실행하지 않는다.
- 기존 네이버 제목·문체 스킬을 필수 의존성으로 삼지 않는다. 저장소의 개인 문체 프로필을 자동 로드하거나 수정하지 않는다.
- 스킬 폴더는 읽는 지침이다. 사용자 원고·상태를 그 안에 저장하지 않는다. 파일 요청이 있을 때만 사용자가 지정한 작업 영역에 저장하고 기존 파일은 허락 없이 덮어쓰지 않는다.

## 연동용 파일 출력

사용자가 파일/네이버 연동 패키지를 요청하면 [파일 출력 계약](references/file-output.md)을 읽는다. 대화 전체가 아니라 공개 본문 전용 article.md, 별도 editorial.json, pending review.json으로 분리한다. 기존 단독 대화 출력은 그대로 유지한다. 검수된 content_revision은 정본 변환 후 연결하며 writer가 임의 해시를 만들지 않는다. 파일 준비는 네이버 입력·이미지 생성·업로드 승인이 아니다.

## 빠른 요청 예시

```text
$seo-series-writer 생활 속 과학을 주제로 10편 목차와 제1편을 작성해줘.
전문가형을 중심으로 초보자도 이해하기 쉽게 쓰고, 완성형 본문 기준을 적용해줘.
```

같은 대화에서는 `다음 편`, `제3편 재작성`, `발행 패키지`, `상태 요약`으로 범위를 지정할 수 있다. 실제 이전 상태가 보이지 않으면 추측하지 않는다.
