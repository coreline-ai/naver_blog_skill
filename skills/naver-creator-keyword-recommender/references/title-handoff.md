# 제목 핸드오프

`recommend`·`recommend-with-home`에서 키워드별 대표 제목을 만들거나 `title-candidates`에서 추가 후보를 만들 때 읽는다.

## 입력 패킷

키워드마다 다음 정보만 `naver-title`의 제목 생성 규칙에 전달한다.

```yaml
keyword: 검색 유입에서 선정한 키워드
search_intent: 독자가 알고 싶어 하는 대상·행동·판단 기준
blog_fit: 기존 블로그와의 직접·인접 관계
evidence: 최근·비교 창 등장일과 카테고리
verified_facts: 현재 확인된 사실만 나열
allowed_patterns: 메인 유입에서 집계한 구조 중 사실성 검수를 통과한 패턴
creator_main_patterns: 최근 메인 유입에서 집계한 패턴 이름·비율
blog_home_patterns: 요청했을 때만 전달하는 홈 피드 패턴 이름·비율
risk_flags: 시의성·인물 평판·의료·금융·정치·법률 위험
```

메인 유입·블로그 홈 제목의 원문과 고유 문구, 블로그 계정·연령 세그먼트는 패킷에 넣지 않는다. `blog_home_patterns`는 `recommend-with-home`에서만 존재하며, 이 필드가 없어도 기존 추천이 동일하게 동작해야 한다.

## 기본 선정

1. 키워드별로 검색형·홈판형·혼합형 후보를 각 1개씩 내부적으로 검토한다.
2. 키워드와 검색 의도가 앞에 보이고, 확인된 정보만 쓴 후보를 우선한다.
3. 본문이 없는 단계에서는 경험, 가격, 날짜, 순위, 품절, 성과를 생성하지 않는다.
4. 기본 `recommend`는 검수를 통과한 대표 제목 1개만 출력한다. 사용자가 여러 개를 요청하면 `title-candidates`로 전환한다.

## 패턴 사용 제약

- **출처 분리:** 검색 유입은 키워드 근거, 메인 유입과 홈 피드는 제목 구조 근거다. 홈에서 발견한 단어를 키워드로 만들지 않는다.
- **패턴 수:** 제목 하나에 주 패턴 1개와 보조 패턴 최대 1개만 적용한다.
- **숫자:** 확인된 기간·비용·개수만 쓴다. `3가지` 같은 구조를 쓰면 후속 본문이 정확히 3개를 충족해야 함을 표시한다.
- **인용:** 사용자가 제공했거나 신뢰할 수 있는 출처에서 확인한 발언에만 쓴다.
- **질문:** 본문에서 직접 답할 수 있는 질문만 쓴다.
- **정보 공백:** `이것`, `정체`, `뭐길래`로 답을 숨기지 말고 독자가 얻을 정보를 알린다.
- **갈등·반전:** 관찰 빈도가 높아도 루머·논란·위기감을 만들기 위해 사용하지 않는다.
- **유사성:** 홈 제목의 고유 어순·인물·사건·수치를 재사용하지 않는다. 우연히 원문과 유사한 후보는 다시 작성한다.

## 출력과 종료

- 추천 표에 `대표 추천 제목`, `적용 패턴`, `위험도`를 함께 적는다.
- 추천 제목은 이후 작성할 본문의 약속이므로 `추천 글 방향`과 모순되지 않아야 한다.
- `본문 미작성`, `아직 글은 작성하지 마`가 있으면 제목 표와 패턴 요약 후 즉시 종료한다.
- 본문·이미지·SmartEditor 작업을 시작하지 않는다.
