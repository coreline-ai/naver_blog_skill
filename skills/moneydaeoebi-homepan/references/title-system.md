# 제목 시스템

이 문서는 제목의 트랙, 사실 경계와 최종 출력 형식을 정한다. 실제 후보 생성·선별 과정은 [제목 실험실](title-lab.md)을 적용하고, 소재 카테고리에 맞는 문장 구조는 [제목 패턴표](title-pattern-matrix.md)에서 고른다.

## 먼저 확보할 재료

- 대상과 사건
- 독자 상황 또는 검색 의도
- 확인된 수치·시간·장면·발언
- 독자가 결정해야 하는 조건
- 아직 확인되지 않아 제목에 넣으면 안 되는 주장

실시간 화제어는 `검색어가 떠 있다`는 관측일 뿐 사건의 진위를 입증하지 않는다. 순위 출처와 사건 출처를 따로 확인한다. 네이버가 공식 실시간 검색어를 제공하지 않는 시점이라면 제3자 집계를 `네이버 실시간 검색어`로 단정하지 않는다.

## 세 가지 제목 트랙

### 검색형

- 방법: `대상 + 방법｜순서·준비물·주의사항`
- 조건: `대상 + 조건｜기간·자격·제외 기준`
- 비용: `대상 + 비용｜가격·수수료·처리 기간`
- 비교: `A와 B 비교｜차이·선택 기준`
- 문제 해결: `증상 + 해결 방법｜원인·확인 순서`

### 홈피드형

- 구체 단서와 숨긴 답: `공연은 10시에 끝나는데 셔틀은 20분 먼저 떠난다`
- 기준 변화: `같은 신청인데 이 조건에서 결과가 달라진다`
- 결과 선공개: `3.2% 급락 개장 뒤 낙폭이 줄어든 이유`
- 실제 장면: `결제 직전 다시 처음으로 돌아간 한 단계`
- 독자 판단: `끝까지 관람할 사람은 먼저 확인할 귀가 시간`

정보 공백을 만들더라도 `이것`, `그 이유`, `충격`만 남겨 대상을 숨기지 않는다.

### 혼합형

`검색 식별어｜구체적인 클릭 이유`를 기본으로 한다.

```text
KTX 취소 환불방법｜출발 전후 수수료가 달라지는 기준
청년지원금 신청조건｜접수 전에 확인할 제외 기준
네이버지도 예약 기능｜식당부터 여행까지 달라진 한 번의 동선
```

## R9 고정 제목 매트릭스

제목 생성 요청은 아래 10개 그룹을 모두 사용한다. 그룹마다 7개 이상의 원형 후보를 만든 뒤 5개만 남겨 총 50개를 출력한다.

1. 확인된 실제 발언
2. 숫자와 규모
3. 예상과 다른 결과
4. 과거에서 현재로의 변화
5. 비교 또는 관계
6. 실제 장면과 행동
7. 사건 이후의 현재 상태
8. 이유·정체·방법·결과의 정보 공백
9. 독자의 상황과 선택
10. 근거 있는 감정 또는 긴장

각 그룹의 최종 5개는 따옴표 스타터 2개와 무따옴표 스타터 3개로 구성한다. 전체 비율은 따옴표 20개, 무따옴표 30개다. 감정 증폭형을 포함해 어느 그룹도 생략하지 않는다. 재료가 부족하면 사실을 창작하지 말고 독자 반응형 또는 가장 가까운 메커니즘으로 대체하고 표시한다. 민감 소재에서는 10번 그룹을 추모·의미·공식 대응형으로 바꾸되 자리와 개수는 유지한다.

모든 주제에서 [제목 실험실](title-lab.md)의 30종 스타터를 전부 적용해 원형을 만든다. 최종 50개에는 서로 다른 메커니즘과 문장 리듬을 남기고, TOP5는 서로 다른 그룹에서 고른다.

## 제목 관문

각 후보에 다음 질문을 적용한다.

- **FACT:** 숫자, 발언, 관계, 상태가 근거와 같은가?
- **CONTEXT:** 대상을 모르는 독자도 상황을 이해하는가?
- **SPECIFIC:** 다른 기사에도 붙는 문장이 아닌가?
- **GAP:** 답을 전부 숨긴 것이 아니라 구체 단서를 남겼는가?
- **PAYOFF:** 원고 초반에서 정직하게 답할 수 있는가?
- **SAME:** 기사나 다른 후보의 첫 구절을 거의 복제하지 않았는가?
- **NATURAL:** 키워드 나열이나 번역투가 아닌가?

하나라도 실패하면 추천 후보에서 제외하거나 고친다.

후보가 둘 이상이면 개별 통과만으로 끝내지 않는다. 첫 구절, 지배적인 각도, 질문형 여부, 사용한 핵심 사실이 서로 충분히 다른지 목록 전체를 검사한다. 이 검사는 [제목 실험실](title-lab.md)의 후보 풀 절차를 따른다.

홈피드형과 혼합형은 최종 추천 전에 같은 소재의 대표 언론사 헤드라인 2~3개를 확인한다. 추천 제목의 첫 10~15자와 같은 직접 인용·숫자·결과가 이미 헤드라인 앞에 반복되면 목록에는 남길 수 있지만 최종 추천은 다른 각도에서 고른다. 검색할 수 없는 환경에서는 발행 전 중복 검색 필요를 명시한다. 검색형은 핵심 식별어를 앞에 두는 편익이 더 크므로 이 검사보다 검색 의도를 우선한다.

## 금지 또는 제한

- 실제 발언이 아닌 서술형 문장을 인용부호로 감싸지 않는다.
- 기사 요약을 당사자의 직접 발언으로 바꾸지 않는다.
- `모두`, `전 국민`, `무조건`, `반드시`, `결국 들통`은 범위가 입증되지 않으면 쓰지 않는다.
- 근거 없는 `최초`, `최대`, `1위`, `몇 년 만`, 비율, 자산·수익 수치를 쓰지 않는다.
- 입력에 없는 체험을 `직접 해보니`로 만들지 않는다.
- 사망, 질병, 범죄 피해, 미성년자 소재에 감정어·추측 훅을 쓰지 않는다.
- 질문형을 반복해 후보 전체를 비슷하게 만들지 않는다.

## 출력 형식

제목 생성 요청은 10개 그룹을 아래 순서로 출력한다. 그룹 이름은 Markdown `###` 제목으로 쓰고, 후보 번호는 1부터 50까지 연속으로 쓴다. 검사기에 전달하는 `titles.txt`에는 그룹 제목·TOP5·추천 이유를 넣지 않고 50개 후보만 한 줄씩 넣는다.

```text
### 1. 실제 발언형 (1~5)
### 2. 숫자형 (6~10)
### 3. 예상전복형 (11~15)
### 4. 시간 변화형 (16~20)
### 5. 비교·관계형 (21~25)
### 6. 장면형 (26~30)
### 7. 후속·현재형 (31~35)
### 8. 정보 공백형 (36~40)
### 9. 독자 상황·판단형 (41~45)
### 10. 감정 증폭형 (46~50)
```

각 그룹의 5개에는 따옴표 스타터 2개와 서로 다른 무따옴표 스타터 3개를 배치한다. 각 제목 끝에는 `[실제 발언]`, `[독자 반응]`, `[무따옴표-N1]`부터 `[무따옴표-N7]` 중 정확히 하나를 표시한다. 홈피드형의 N6와 N7 최소 개수는 이 표시를 기준으로 검사한다. 감정어 근거가 없어 10번 그룹을 바꾸면 `[감정대체]`, 민감 소재면 `[민감대체]`를 추가한다.

50개 다음에는 서로 다른 그룹에서 고른 TOP5와 최종 추천 1개를 적는다. TOP5와 최종 추천 문장은 목록에서 스타터·대체 라벨을 제외한 제목 본문과 글자 하나까지 같아야 한다. 추천 이유에는 가짜 CTR·확률·점수를 쓰지 않고, 구체 단서와 숨긴 답을 설명한다. [R9 검사 매니페스트](r9-audit-manifest.md)에 선택 번호와 같은 문장을 기록해 일치를 검사한다.

분석을 함께 요청받으면 아래 진단도 앞에 붙인다.

```markdown
## 입력 진단
- 핵심 주제:
- 독자 상황 또는 검색 의도:
- 확인된 사실:
- 확인 필요:

## 제목 후보
1. ...

## 최종 추천
- ...

## 검수 메모
- 본문에서 반드시 답할 내용:
- 추가 확인이 필요한 표현:
```
