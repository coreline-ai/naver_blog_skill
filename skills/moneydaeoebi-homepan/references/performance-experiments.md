# 성과 진단과 실험

## 먼저 분리할 것

성과 수치는 플랫폼 화면의 실제 필드명과 기간을 그대로 기록한다. 다음 항목을 임의로 합산하지 않는다.

- `네이버 메인_모바일_홈판`
- `네이버 블로그_모바일`
- 검색 유입
- 기타 추천·외부 유입

사용자가 합산 지표를 요청하거나 분석 목적상 합산할 때는 원래 값도 함께 남긴다. 유입 경로 이름이 바뀌었으면 현재 화면 정의를 우선한다.

## 최소 기록

```text
글 ID 또는 URL:
주제와 카테고리:
발행 시각:
측정 시각과 경과 시간:
제목 트랙과 사용한 각도:
대표 이미지 종류:
각 유입 경로 수 또는 비율:
노출·조회·클릭 지표의 화면상 정의:
댓글·저장 등 반응:
검색 반영 여부:
같은 날 발행 편수:
특이 사항:
```

## 진단 순서

1. 비교 기간과 분모가 같은지 확인한다.
2. 검색 반영 누락, 게시 상태, 측정 지연 같은 데이터 문제를 먼저 제외한다.
3. 노출 부족과 노출 후 반응 부족을 구분한다.
4. 제목, 대표 이미지, 소재, 발행 시각을 한꺼번에 바꾸지 말고 다음 글에서 한두 변수만 바꾼다.
5. 한 건의 성공·실패를 보편 규칙으로 만들지 않는다.

## 해석 가능한 가설

- 노출 자체가 적음: 소재의 현재성, 카테고리 적합성, 검색 반영, 채널 상태를 확인한다.
- 노출은 있으나 클릭 반응이 약함: 제목 첫 단서, 대상 식별, 대표 이미지와 제목의 역할 분담을 본다.
- 클릭 후 반응이 약함: 제목 답을 주는 위치, 초반 반복, 본문 추가 가치, 모바일 가독성을 본다.
- 검색 유입만 강함: 검색형 자산으로 유지하고 억지로 홈피드형으로 바꾸지 않는다.

## 실험과 레거시 규칙

- `5% 미만 / 5~20% / 20% 이상` 구간은 원본 R9의 **LEGACY EXPERIMENT**다. 네이버 공식 기준이나 일반 법칙으로 사용하지 않는다. 사용자가 R9 호환 진단을 요구할 때만 표본 기간·분모와 함께 표시한다.
- `하루 3개 이하`, `분 단위 불규칙 예약`도 공식 근거가 없는 **LEGACY EXPERIMENT**다. 기본 발행 규칙으로 강제하지 않는다.
- 최소 20건처럼 비교 가능한 표본이 모이면 제목 각도, 소재, 이미지, 발행 시각별 차이를 살펴볼 수 있다. 그래도 인과관계가 아니라 관측 가설로 표현한다.

## 결과 형식

```markdown
## 관측
- 실제 수치와 범위

## 데이터 한계

## 가능한 원인
1. 근거가 강한 가설
2. 확인이 필요한 가설

## 다음 실험
- 유지할 변수:
- 바꿀 변수:
- 판단 시점과 지표:
```
