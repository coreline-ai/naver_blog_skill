## 개발 목적

기존 `naver-blog-style` 및 `naver-series-workflow`가 원고에서 이미지 목적·소제목·본문 근거를 읽고, 일반 이미지·정보 슬라이드·혼합형의 장별 프롬프트를 재사용 가능한 도우미로 만들도록 한다.

### 호환성 경계

- 일반 원고의 소제목·요약은 기존 `build_naver_post.py` 원고 구조와 연결하는 작은 어댑터로 읽는다. 마크다운/HTML 파서를 새로 중복 구현하기 전에 기존 파서 API와 지원 블록을 확인한다.
- 순서가 확정된 슬롯에서는 앞 N개 선택을 원본과 비교한다. 수량이 부족하면 `requested_count`, `selected_count`, 부족 이유를 보고하고 완료나 시리즈 입력 준비로 승격하지 않는다.
- v2 이미지 포함 완성형의 `cover 1 + inline 2 이상`, 전문가형 기본 목표 5장, H1 직후 대표 배치는 유지한다. 단일 슬라이드 요청에 이 하한을 임의 적용하지 않는다.
- `info-slide`는 기존 manifest에서 `mode: infographic-diagram`으로 연결한다. `standard`/`mixed`는 기존 매체 선택을 사용한다. 기존 manifest의 허용 mode 목록·버전을 바꾸지 않는다.
- 생성 계획과 승인 manifest는 별도 산출물이다. 프롬프트가 준비됐다는 이유로 `status: approved` 또는 `visual_ready`를 기록하지 않는다.
- 4:5 및 1080×1350은 원본 프롬프트의 요청 규격이다. 실제 결과 파일의 크기·가독성·문구 검수가 통과한 사실과 구분한다.
