## 스킬 책임과 발동 경계

### 책임

- 원고 생성이 아니라 완성 원고의 SmartEditor 입력을 담당한다.
- 입력을 검증하고 회차별 순차 실행을 관리한다.
- 실제 화면 상태를 확인한 뒤에만 다음 동작을 선택한다.

### 발동 조건

다음과 같이 SmartEditor 입력 의도가 명시된 요청에서만 사용한다.

- `네이버 스마트에디터에 작성해줘`
- `네이버 블로그 초안을 입력하고 임시저장해줘`
- `제3편부터 제15편까지 이미지 포함해서 순서대로 작성해줘`

일반적인 블로그 글쓰기, SEO 원고 생성, 이미지 생성 요청에는 발동하지 않는다.

```text
제3편부터 제15편까지 총 13개 Markdown 원고를 지정된 네이버 SmartEditor에
한 편씩 순서대로 작성한다.

각 회차는 제목, 본문, 소제목, 목록, 이미지 5장, 태그를 원본 순서대로 입력한다.
작성 전 SmartEditor가 빈 화면인지 확인하고, 작성 후 내용을 검증해 임시저장한다.

임시저장 성공을 확인한 뒤 새 글쓰기 화면으로 이동하고, 제목·본문·이미지가 없는
빈 화면인지 다시 확인한 경우에만 다음 회차를 진행한다.

기존 내용, 중복 입력, 이미지 업로드 실패, 저장 불확실성이 발견되면 중단하고

```

`agents/openai.yaml`의 UI용 기본 프롬프트는 특정 회차나 블로그 ID를 고정하지 않고 같은 안전 규칙을 짧게 요약한다.

## 입력 계약

### Markdown 입력

- 첫 H1은 제목이다.
- 이미지 문법 위치가 실제 이미지 삽입 순서다.
- 태그 섹션은 본문에서 분리한다.
- 지원하지 않는 문법은 임의 삭제하지 않고 경고 또는 오류로 처리한다.

### `naver-post/v1`

```json
{
  "schema": "naver-post/v1",
  "episode": 3,
  "source": "episode-03.md",
  "title": "흔들린 사진과 실패한 사진을 빠르게 골라내는 기준",
  "blocks": [
    {"id": "b001", "type": "image", "path": "/absolute/01-cover.png", "alt": "..."},
    {"id": "b002", "type": "heading", "level": 2, "text": "..."},
    {"id": "b003", "type": "paragraph", "text": "..."}
  ],
  "tags": ["흔들린사진", "실패사진정리"]
}
```

- 모든 블록은 회차 안에서 고유한 ID를 가진다.
- 이미지는 실제 존재하는 절대경로, 대체텍스트, 원본 순서를 가진다.
- 이미지 프롬프트만 있고 파일 경로가 없으면 `draft` 검증에 실패한다.
- 사용자 제공 JSON의 `steps`, `comparison`, `callout`, `checklist`는 표준 블록으로 정규화한다.

## 브라우저 상태 머신

```text
PREPARED
→ EDITOR_READY
→ BLANK_VERIFIED
→ WRITING
→ CONTENT_VERIFIED
→ SAVED_VERIFIED
→ NEW_EDITOR_READY
→ 다음 회차
```

어느 단계에서든 검증이 실패하면 `STOPPED`로 전환하고 이후 회차를 실행하지 않는다.

### 화면 확인 기준

- 열린 탭에서 네이버 글쓰기 URL과 대상 블로그를 확인한다.
- 로그인 화면이 아닌 편집기인지 확인한다.
- 제목 입력란, 본문 편집 영역, 임시저장 기능을 접근성 트리에서 확인한다.
- 접근성 정보가 불충분할 때만 실제 화면 캡처를 보조 증거로 사용한다.
- UI 행동 뒤에는 새로운 접근성 상태를 읽어 성공 여부를 확인한다.

### 빈 화면 기준

- 제목 문자열이 비어 있다.
- 본문에 플레이스홀더 이외의 텍스트가 없다.
- 본문 이미지와 첨부 블록이 0개다.
- 복구 대기 중인 미저장 초안이 없다.

### 임시저장 후 전환

- 임시저장 완료 알림 또는 저장 상태 변화를 확인한다.
- 저장 직후 제목과 주요 본문이 유지되는지 확인한다.
- 본문을 선택·삭제하지 않고 `새 글 작성` 흐름으로 전환한다.
- 새 화면이 빈 상태임을 확인한 뒤 이전 편집 탭을 정리하고 다음 회차를 시작한다.

## 이미지 삽입 방식

- Markdown 파서가 텍스트와 이미지의 순서를 하나의 블록 배열로 만든다.
- `image` 블록에 도달했을 때만 해당 로컬 파일을 업로드한다.
- 이미지 미리보기 또는 이미지 블록이 나타난 것을 확인해야 다음 블록으로 진행한다.
- 소제목 문자열 검색이 아니라 고유 블록 순서로 위치를 결정한다.
- 이미지가 실패하면 해당 회차를 저장 가능한 안전 상태로 두고 전체 실행을 중단한다.
- 사용자 실행 요청에 이미지 업로드가 명시되지 않았다면 첫 파일 업로드 직전에 확인한다.

## 실행 기록

회차 상태는 다음 중 하나로 기록한다.

```text
pending → prepared → writing → saved_verified
                         └→ failed
```

- `preflight-report.json`: 제목, 블록 수, 이미지 수·경로, 태그 수·길이
- `draft-run-report.json`: 입력 블록 수, 대체 서식, 저장 검증 결과, 실패 위치
- `run-report.json`: 13개 회차의 전체 진행 상태와 마지막 성공 회차
- 화면 캡처는 기본적으로 영구 저장하지 않고, 사용자가 요청하거나 실패 증거가 필요할 때만 민감 정보 노출 여부를 확인해 저장한다.

## 중단·복구 규칙

- 기존 내용이 있으면 자동 삭제하지 않는다.
- 같은 제목과 선두 문단이 있으면 재입력하지 않고 중복 가능성을 보고한다.
- 새 글 화면이 빈 상태가 아니면 다음 회차를 시작하지 않는다.
- 파일 선택 권한이 없으면 설정 우회 없이 필요한 권한을 안내한다.
- 이미지, 본문, 태그 개수가 기대값과 다르면 임시저장 여부를 보고하고 중단한다.
- 저장 성공 신호가 없으면 새 글 화면으로 이동하지 않는다.
- UI 요소 탐색이 연속 두 번 실패하면 무한 재시도하지 않는다.
- 재시작 시 `run-report.json`과 실제 편집기·임시저장 상태를 대조한 뒤 이어갈 위치를 정한다.
