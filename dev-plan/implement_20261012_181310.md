### 최소 책임과 산출물

- `research-request.json`: schema, keyword, search_source, requested_reference_count, count_origin(default/explicit). 비활성화는 호출 경계에서 처리한다. 이미지의 requested_count와 공유하지 않는다.
- `research-snapshot.json`: 요청 정보, 실제 search_url·collected_at·collection_method, attempted_count·valid_body_count·status, references와 failures. reference는 고유 ID·관찰 순서·원래/최종 URL·title·snippet·headings·content·원문/보존 길이·잘림 여부·수집 상태를 가진다.
- `research-context.md`: 검증된 snapshot에서 만든 제한된 참고 문맥. snippet과 실제 content를 구분하고 외부 자료임을 표시한다.
- `research-brief.md`: 에이전트가 작성한 검색 의도·공통 주제·비교점·누락/상충 정보·새 구성·검증할 주장과 reference ID/URL 연결. 이후 사실 확인 결과와 사용/제외 이유를 덧붙인다.
- 기존 `article.md`, 이미지 request/plan, manifest, 합성 원고를 후속 단계에서 그대로 사용한다. 새 참고 schema는 기존 이미지·wizard schema에 넣지 않는다.

### 수집·길이·완료 경계

- 참고 수 1~8은 명시 범위이며 0·9 이상·비정수는 조용히 보정하지 않는다. 검색 결과의 순서는 해당 시각의 관찰 순서이고 보편적인 검색 순위·인기 순위가 아니다.
- 유효 본문은 실제 게시물에서 관찰한 주요 본문이다. 원본의 180자 기준을 최소 추출 기준으로 재사용하되, 검색 snippet·메뉴·댓글만 180자를 넘긴 결과는 제외한다. 내용 적합성은 에이전트가 별도 검토한다.
- 같은 게시물의 모바일·PC URL은 하나로 센다. 광고 표시·비관련 글은 제외 이유를 기록하고, 가능한 후보가 부족해도 중복으로 수량을 채우지 않는다.
- 검색 후보는 첫 결과 화면에서 최대 2×N개(최대 16개)까지만 확인하고, 게시물당 짧은 대기 후 재확인은 한 번으로 제한한다. 별도 검색 페이지 순회나 차단 우회는 하지 않는다.
- 원본 `buildBackendResearchPayload`의 글당 6,500 / 전체 본문 24,000 및 `formatResearchContext`의 25,000 문맥 예산 계산을 확인해 이식한다. JS UTF-16 길이·메타데이터·들여쓰기·말줄임표 때문에 발생하는 차이를 fixture로 기록한다. 대상 최종 문맥은 메타데이터 포함 25,000 UTF-16 units 이내이고 Unicode를 손상시키지 않도록 한다. 이 보완을 원본과 완전히 동일하다고 표시하지 않는다.
- `complete`는 N개의 고유 유효 본문 확보, `partial`은 1~N-1개, `unavailable`은 0개다. 잘린 문맥을 본문 전문이라고 표시하지 않는다. 실패 항목은 유효 reference와 별도로 남긴다.
- 명시 N개의 partial/unavailable은 참고 요구 미충족이다. 가능한 준비는 진행하되 전체 요청 완료로 보고하지 않는다. 기본 5개가 partial이면 확보된 범위로 작성할 수 있으나 실제 참고 수·제약을 별도 결과 메모에 밝힌다.
- 본문이 한 개뿐이면 한 글의 관점으로만 분석한다. 공통 패턴은 실제 두 개 이상에서 확인하고 ID를 연결한다. unavailable에서는 블로그 참고 분석을 생략하고 공식 자료 기반 작성 가능 여부를 따로 보고한다.
- 블로그의 반복 언급은 구매 비중·판매 순위·검증된 사실이 아니다. 날짜·가격·정책·수치·효능은 적절한 공식 자료로 확인하고, 타인의 경험은 타인의 관찰로 취급한다.
- 참고 자료 변경 뒤 원고가 바뀌면 기존 제목·원고 SHA·이미지 계획 최신성 규칙을 적용한다. 자료 파일만 갱신됐다는 이유로 정상 이미지를 자동 재생성하지 않는다.
