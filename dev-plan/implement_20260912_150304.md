## 2. 목표 동작 방식

```text
사용자 요청
 → 모드·시리즈·요청 회차 집합·이미지 요구·대상 블로그 확인
 → 기존 원고 재사용 또는 요청 회차 작성
 → 본문 / 편집 메모 / 검수 결과 분리
 → 이미지 슬롯 준비 → 실제 파일 확인 → 지정 위치 합성
 → 전체 요청 범위·정본·이미지·검수 사전검증
 → [prepare이면 종료: 브라우저 변경 0]
 → [draft/resume 명시 요청] 이력 대조·잠금·현재 화면 확인
 → 한 회차 입력 → 전체 입력 검증 → 임시저장 확인
```

| 모드 | 허용 동작 | 종료 기준 |
|---|---|---|
| `prepare` 기본 | 요청된 원고/이미지 준비, 파일 변환·검수 | 전체 요청 집합 사전검증. UI 조작 없음 |

## 3. 입출력 계약과 버전

### 3.1 최소 시리즈 계약 — 신규 `naver-series/v1`

아래는 **구현 예정 예시**다. 경로는 manifest 위치 기준으로 해석하고 허용 입력 루트 안에 있어야 한다.

```json
{
  "schema": "naver-series/v1",
  "series_id": "Series-CF-4192",
  "requested_episodes": [3, 4, 5],
  "target_blog": "antifreeid",
  "requirements": {"images_per_episode": 5, "tag_line_max_chars": 100},
  "episodes": [
    {"episode": 3, "article": "episode-03/article.md", "editorial": "episode-03/editorial.json", "review": "episode-03/review.json"},
    {"episode": 4, "article": "episode-04/article.md", "editorial": "episode-04/editorial.json", "review": "episode-04/review.json"},
    {"episode": 5, "article": "episode-05/article.md", "editorial": "episode-05/editorial.json", "review": "episode-05/review.json"}
  ]
}
```

새 이미지 합성이 필요하면 회차에 `image_slots` 경로를 추가한다. 준비 전용에서는 대상 블로그를 생략할 수 있지만 UI 실행 전에는 명시적으로 확정한다.

### 3.2 회차 산출물

| 파일 | 의미 / 검증 |
|---|---|
| `article.md` | 게시할 H1·본문만 포함. 임의 문자열 삭제로 메모 제거 금지 |
| `editorial.json` | 목차·키워드 후보·작성 메모. 에디터 입력 대상에서 제외 |
| `review.json` | `pending/passed/needs_revision`, 확인 항목·근거·검토 대상 버전 |
| `image-slots.json` | 합성 시 기존 v1 슬롯 계약 재사용. 실제 파일·배치 사유·캡션·승인 상태 |
| `naver-post.json` | 기존 `naver-post/v1` 순서형 블록. canonical 재입력 시 marks 포함 보존 |
| `asset-integrity.json` | 이미지 SHA-256·형식·픽셀·파일 크기. 별도 무결성 sidecar |
| `preflight-report.json` | 구조·본문 경계·검수·이미지·범위 결과. UI 성공 상태는 기록하지 않음 |

- 이미지가 이미 들어 있는 Markdown은 그 순서를 유지하고 슬롯을 강제로 다시 만들지 않는다.
- 메모 경계가 모호하면 `EDITORIAL_BOUNDARY_AMBIGUOUS`로 멈춘다. 단순 문자열 삭제로 본문을 손상시키지 않는다.
- 정보성 워크플로는 실질 본문이 필요하다. 이미지·태그만으로 통과하지 않으며 고정 글자 수로 품질을 판정하지 않는다.
- `review=passed`는 검토 항목·근거·대상 버전이 있어야 한다. 원고/이미지·캡션 변경 시 재검토한다. 승인·사실의 절대 정확성 보증은 아니다.

### 3.3 버전과 쓰기 경계

- `content_revision`은 정규화된 게시 정본·순서 있는 이미지 해시·태그·서식 정책 버전으로 계산한다. 절대 경로나 시각만 바뀌어도 새 내용으로 판정하지 않는다.
- 원본 파일 해시는 provenance로 별도 저장한다. 검수 파일은 검토 대상 revision을 가리켜 순환 해시를 만들지 않는다.
- 파일명·상위 회차 폴더·JSON 내부 회차가 명시되면 모두 일치해야 한다. 확정 불가 회차는 추측하지 않는다.
- 모든 출력 경로·회차 충돌은 쓰기 전에 검사한다. 회차별 오류는 수집하되 전체 요청 집합이 통과하기 전에는 UI 큐를 실행 가능으로 만들지 않는다.
- 준비 파일은 별도 staging에 쓴 뒤 완료 manifest를 마지막에 확정한다. 미완료 staging은 성공으로 읽지 않는다. 파일 원자적 쓰기를 배치 전체 원자성으로 과장하지 않는다.
- 동일 결과는 재사용하고 변경은 새 revision으로 준비한다. 준비 CLI는 실행 이력을 쓰지 않는다. `--force`는 resume 수단이 아니다.

## 4. 이미지와 서식 적용 정책

| 입력 | 기본 적용 | 확인·실패 정책 |
|---|---|---|
| H1 | 제목 필드 | 제목 전용 영역1개, 문자열 대조 |
| H2 | 말풍선 인용구 `quotation_bubble` | 과거 인용구3. 현재 UI 역할·모양 재확인 |
| 핵심 요약 | 라인형 `quotation_line` | 요약 **제목 라벨만** 적용. 요약 목록 전체를 감싸지 않음 |
| 예고·질문 레이블 | 정본 style에 따른 라인형 | 정본에 없는 인용구 추가 금지 |
| 문단·강조 | 순서·문자열·bold 범위 보존 | 전체 문단 선택 검증. 줄 단축키만으로 판단 금지 |
| H3·목록·표 | 기존 지원 범위의 소제목/번호·불릿/레이블 문단 대체 | 대체 매핑을 preflight에 기록. 완전한 표 보존이라고 주장하지 않음 |
| 출처 링크 | 설명과 URL 모두 유지 | 기본은 `설명 (URL)` 명시적 텍스트 대체. 링크 UI 지원 시 href도 검증 |
| H4·fenced code·미지원 문법 | 기본 거부 | 조용한 손상·미지원 문법의 무경고 통과 금지 |
| 이미지 | 정본 이미지 블록 위치에서 업로드 | 개수·순서·앞뒤 anchor·로딩 완료·표시 상태 확인 |
| 태그 | 본문과 분리하여 태그 UI 입력 | `#태그1 #태그2` 공백·# 포함100자 이하, 재열기 지속성 확인 |

새 글의 이미지5장은 표지·개념·실전·체크포인트·요약 흐름을 후보로 삼되 관련성에 맞춰 배치한다. 위치가 지정된 원고는 임의로 균등 분배하거나 이동하지 않는다. 이미지 프롬프트는 파일이 아니다.

이미지는 실제 디코딩으로 검증한다. 초기 지원은 PNG/JPEG이며 나머지는 명시적으로 거부한다. Pillow는 현재 환경에서 발견됐지만 다른 환경에서는 가용성을 검사하고, 없을 때 검증을 생략하지 않는다. 파일/픽셀 상한은 자체 안전 한도로 문서화하며 네이버 공식 한도라고 표현하지 않는다.

업로드 직전 이미지 해시를 재확인한다. 네이버의 재인코딩 가능성 때문에 원격 바이트 해시 동일성은 요구하지 않는다. 투입 파일 기록과 실제 표시 이미지·순서·앞뒤 본문을 대조하고 식별이 애매하면 검증 보류한다.

## 5. 실행 상태·중복 방지·복구

```text
ready → editor_checked → inserting → input_verified
 → save_requested → save_acknowledged → reopened_verified
 → blank_verified → 회차 완료

관찰 실패/중단 → needs_reconciliation 또는 save_unknown
버전 불일치 → revision_conflict
```

- 준비 상태와 UI 상태를 분리한다. 실행 이벤트 정본은 drafter의 저장소 하나로 관리하며 총괄 스킬은 조회한다.
- 중복 키는 `(series_id, episode, target_blog, content_revision)`. 동일 회차 다른 revision은 새 글 생성이 아니라 충돌이다.
- 입력·업로드·저장 부작용 직전에 operation id와 의도를 기록하고 이후 관찰 결과를 별도 이벤트로 기록한다. 기록 확정 실패 시 UI 작업도 하지 않는다.
- 저장 요청 후 결과가 없으면 `save_unknown`. 재클릭/새 글 생성 전에 현재 편집기·임시저장 목록을 대조한다.
- 초안 식별은 지원 UI에서 관찰한 식별자와 제목·시간·내용 증거를 결합한다. 동일 제목 후보가 여럿이면 멈춘다. 비공개 API로 ID를 추출하지 않는다.
- 동일 revision이 `reopened_verified`이면 재작성하지 않는다. 마지막 빈 화면 전환만 미완료면 그 단계부터 대조한다.
- 이벤트는 원자적으로 확정하는 개별 파일로 보존하고 집계는 재생성 가능하게 한다. 손상 이벤트를 건너뛰고 성공 처리하지 않는다.
- 대상 블로그당 잠금. 초기 범위는 단일 호스트·단일 지정 실행 저장소다. 다른 저장소/기기나 수동 편집까지 잠금으로 방지한다고 주장하지 않는다.
- 오래된 잠금은 시간만으로 해제하지 않는다. 소유 실행 생존 여부·미완료 UI 작업을 대조한 뒤 복구한다.

### 관찰 증거와 안전 경계

각 단계는 `expected`, `observed`, `verification`, `timestamp`, `evidence_ref`를 구분한다. 미관찰값은 `null`과 사유를 남긴다. 제목·모든 텍스트/인용구·이미지 순서/anchor·태그를 대조하고 단순 합계로 대체하지 않는다. NBSP·개행은 비교 전용 정규화로 처리하고 원문 자체는 바꾸지 않는다. marks의 코드포인트와 JavaScript UTF-16 인덱스 차이도 검증한다.

`blank_verified`는 제목·모든 본문/인용구/표·미디어·복구/불러오기 대기 UI 전체에 내용이 없음을 확인한 상태다. 빈 문단1개만으로 판정하지 않는다. 전체 구조를 검사할 수 없으면 `unknown`으로 중단한다.

태그 UI가 발행 설정 안에 있으면 **설정 진입**과 **최종 발행 제출**을 별도 상태·대상으로 식별한다. 같은 이름의 `발행` 버튼 반복 클릭을 금지한다. 최종 제출은 허용 동작에 포함하지 않으며 역할이 불명확해지면 중단한다.

### 기존 기록 이관

기존 `saved_verified`는 `legacy_saved_reported`로 읽고 원문 상태도 보존한다. 기존 보고서를 수정하거나 실제 재열기 없이 `reopened_verified`로 승격하지 않는다. 저장이 보고된 회차는 기본 재생성 금지 대상이고, 필요한 대조는 사용자 지정 범위에서만 한다.
