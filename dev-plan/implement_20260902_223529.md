## 개발 목적

네이버 블로그 원고의 문맥과 분위기를 분석해 대표 이미지와 소제목별 이미지를 기획·생성·검수하고, 승인된 이미지를 Markdown 원고의 정확한 위치에 삽입하는 선택형 `Visual Composer` 모드를 기존 `naver-blog-style` 스킬에 추가한다.

이미지 개수를 기계적으로 채우지 않고 글의 이해, 분위기 전환, 비교 설명에 실제로 도움이 되는 위치만 선택한다. 실사·창작·인포그래픽을 문맥에 맞게 고르면서도 기존 개인 문체와 네이버 콘텐츠 가드레일은 그대로 유지한다.

## 개발 범위

- `SKILL.md`에 이미지 요청 감지, 시각 구성 모드 라우팅, 출력 계약, 실패 처리 규칙을 추가한다.
- 문맥 기반 이미지 위치 선정, 실사·창작·인포그래픽 선택, 스타일 일관성, 시각 QA 절차를 참고 문서로 분리한다.
- 이미지 슬롯과 로컬 파일 정보를 연결하는 JSON manifest v1 계약을 정의한다.
- Markdown 슬롯 마커를 이미지·대체텍스트·캡션으로 치환하는 표준 라이브러리 기반 CLI를 구현한다.
- CLI의 정상·오류·경계 조건을 `unittest`로 검증한다.
- 대표 이미지와 본문 이미지가 포함된 현실적인 블로그 원고로 통합 스모크 테스트를 수행한다.
- README에 사용법, 출력 구조, 안전 가드레일을 문서화한다.

## 문서 기반 제약 사항

- 이미지 생성은 사용자가 대표 이미지, 본문 이미지, 이미지 삽입 등을 명시적으로 요청했을 때만 실행한다.
- 이미지가 필요하지 않은 일반 글쓰기 요청은 기존 텍스트 전용 흐름을 그대로 사용한다.
- 새 이미지는 기본적으로 내장 이미지 생성 도구를 사용하고, 프로젝트에 쓰는 최종 이미지는 `assets/<post-slug>/` 아래에 보존한다.
- 앱 사용법, 거래 주문, 정책 신청처럼 화면 정확성이 중요한 경우 생성 UI 대신 사용자 캡처나 공식 자료를 우선한다.
- 한국어 텍스트가 이미지의 핵심이 아니라면 이미지 안에 글자를 넣지 않고 캡션과 본문 텍스트로 전달한다.
- 생성 실사는 실제 경험의 증거로 오해되지 않도록 필요할 때 `이해를 돕기 위한 이미지`로 구분한다.
- 생성 실패나 QA 불합격 시 최대 1회의 목적이 분명한 수정 생성을 허용한다. 이후에는 실패 슬롯과 이유를 보고하고 무한 재시도하지 않는다.
- 삽입 도구는 원본 원고를 기본적으로 덮어쓰지 않고 별도 출력 파일을 만든다.
