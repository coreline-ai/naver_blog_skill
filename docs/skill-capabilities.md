# 현재 스킬 기능과 사용 예제

기준일: **2026-10-23**. 현재 저장소에 구현된 **기본 스킬 1개·전용 스킬 8개, 총 9개**의 작업 트리와 각 `SKILL.md`를 기준으로 정리했다. 구현된 기능, 이전 검증 기록, 아직 확인하지 않은 실행 환경을 구분한다. 사용자 명시 조건이 기본값보다 우선하며, 세부 계약은 연결된 스킬·reference를 따른다. R9 홈피드 제목은 일반 제목 스킬과 별도로 50개 매트릭스를 사용한다.

## 1. 어떤 스킬을 사용할까?

| 요청 | 스킬 | 결과 | 요청 예시 |
|---|---|---|---|
| 주제로 글을 쓰거나 기존 글을 수정 | [naver-blog-style](../SKILL.md) | 저장된 문체를 적용한 단일 원고, 요청 시 이미지 포함 원고 | 돈키호테 쇼핑리스트를 카드뉴스 5장과 함께 완성해줘. |
| 옵션을 한 질문씩 선택하며 작성 | [naver-blog-wizard](../skills/naver-blog-wizard/SKILL.md) | 확정 원고·이미지 계획·요청한 이미지 패키지와 재개 가능한 세션 | 기존 원고에 이미지만 추가할게. 옵션을 한 질문씩 물어봐. |
| 제목만 생성·개선 | [naver-title](../skills/naver-title/SKILL.md) | 검색형·홈판형·혼합형 후보와 추천 | 네이버 제목 일본 여행 결제수단 비교 |
| 실시간 화제어·기사로 홈피드 콘텐츠 기획 | [moneydaeoebi-homepan](../skills/moneydaeoebi-homepan/SKILL.md) | 검증된 주제·제목·원고·이미지 브리프·성과 진단 | 이 기사로 R9 제목 50개와 TOP5·최종 추천을 만들어줘. |
| 실제 유입을 보고 다음 주제 선정 | [naver-creator-keyword-recommender](../skills/naver-creator-keyword-recommender/SKILL.md) | 추천 키워드·대표 제목·집계 패턴·수집 상태 | 완료된 최근 7일 유입으로 다음 주제와 대표 제목을 추천해줘. |
| 월별 시즌 글감으로 기획·작성·갱신 | [naver-seasonal-blog-writer](../skills/naver-seasonal-blog-writer/SKILL.md) | 월별 추천·실제 원고·검수·버전·블로그별 로컬 이력 | 이번 달 주제 추천 후 선택한 2번으로 작성하고 이력에 남겨줘. |
| 연재를 기획하고 한 편씩 작성 | [seo-series-writer](../skills/seo-series-writer/SKILL.md) | 전체 목차와 요청한 회차 원고 | 일본 자유여행 준비 5편의 목차와 제1편을 작성해줘. |
| 여러 편의 원고·이미지 패키지 준비 | [naver-series-workflow](../skills/naver-series-workflow/SKILL.md) | 검수 상태와 네이버 입력용 준비 패키지 | 5편에 회차별 이미지 5장을 넣어 prepare로 준비해줘. |
| 완성 원고를 네이버에 입력·임시저장 | [naver-smarteditor-drafter](../skills/naver-smarteditor-drafter/SKILL.md) | 사전검증 또는 입력·저장·재열기 확인 기록 | 검수한 원고와 이미지 5장을 지정 블로그에 넣고 임시저장해줘. |

저장소를 작업 폴더로 사용하면 해당 스킬 파일을 직접 읽도록 요청한다.

```text
이 저장소의 SKILL.md를 읽고 네이버 블로그 스킬을 적용해줘.
주제: 일본 여행 전 준비할 결제수단.
초보 여행자를 위한 비교형 글로 작성해줘.
```

아래의 `$스킬명` 예제는 설치·등록된 환경 기준이다. 폴더나 `agents/openai.yaml`이 존재하는 것만으로 전역 설치·자동 선택 성공을 의미하지 않는다. 문답형과 공통 이미지 도우미를 쓰는 흐름은 저장소의 공통 파일·sibling 스킬을 참조한다. 월별 시즌 작성 스킬은 자기 폴더만으로 동작하는 별도 경로다.

## 2. 기본값과 적용 범위

| 항목 | 현재 기본값 | 적용 조건 |
|---|---|---|
| 저장된 문체 | [스타일 프로필](naver-blog-style-profile.md) 적용 | 기본 단일 글 작성. 문체 인터뷰는 요청 시 시작 |
| 글 유형 | 후기·가이드·일기·공지·비교·홍보 링크형에 맞춰 구성 | 제공한 경험·자료 범위 안에서 작성 |
| 기존 블로그 본문 참고 | 블로그 서비스 검색에서 고유 본문 5개 | 새 정보형·방법형·비교형 글. 지정 가능한 참고 수는 1~8개 |
| 통합 작성 제목 | 검색형·홈판형·혼합형 각 3개 내부 비교 → 혼합형 최종 1개 | 기본 글쓰기 흐름. 고정 제목·명시 유형·개수 우선 |
| 일반 제목 전용 요청 | 검색형 5개·홈판형 5개·혼합형 3개 | 유형·개수가 없는 일반 `naver-title` 요청 |
| 제목 단축 요청 | 검색형 4개·홈판형 3개·혼합형 3개 + 최종 추천 | `네이버 제목/타이틀/주제 …` |
| 홈피드 편집 제목 | R9 10그룹 × 5개 = 50개, TOP5, 최종 추천 1개 | `moneydaeoebi-homepan`의 모든 제목 생성 요청 |
| 홈피드 편집 여러 주제 제목 | 요청 전체 50개 안에 모든 주제 포함 | 각 주제에 30종 스타터를 내부 적용한 뒤 그룹별 후보 배치 |
| R9 제목 형식 | 그룹마다 따옴표 2개·무따옴표 3개, 전체 20개·30개 | 감정어 상한·민감 대체·기계적 어미·말줄임표 제한 포함 |
| 이미지 없는 글 | 이미지 생성 생략 | 글 작성만 요청 |
| 이미지 포함 단일 글 | 표지 포함 총 5장 | 이미지 포함을 요청하고 장수는 생략한 경우. 명시 N은 정확히 N장 |
| 문답형 이미지 자동 장수 | 추천 5장을 질문에서 확인 후 적용 | 문답형의 미응답·기본 선택은 확정 답변이 아님 |
| 카드뉴스 비율 | `info-slide`는 실제 4:5 검사, 권장 1080×1350 | 권장 픽셀과 동일한 결과를 보장하지 않음. 혼합형의 본문 카드도 해당하며 임의 비율 전환은 미구현 |
| 일반형 정보 도해 비율 | 대표 1:1·본문 16:9 등 장별 요청으로 구성 | `standard` 안의 `infographic-diagram` 등으로 프롬프트와 실제 검수에 반영. `info-slide` 4:5 완료 검사와 구분 |
| 공개 원고의 출처 | 말미에 클릭할 수 있는 출처명으로 정리 | 루트·통합 준비 흐름. 명시 본문 인용 요청은 우선하며 독립 시즌 스킬은 자체 지침 적용 |
| 연재 편수 | 15편 | 편수·목차·작성 범위 지정 시 그 조건 우선 |
| 연재 작성 프로필 | `expert + friendly` | 전문가형·스토리형·후기형·친숙한 설명형·문제 해결형·비교 선택형 중 지정 가능 |
| 완성형 연재 본문 | 편당 최소 3,000자 | 제목·태그·참고 URL·이미지 정보·편집 메모 제외 |
| 이미지 필수 연재 | 표지 1장 + 본문 2장 이상, 총 최소 3장 | 전문가형 미지정 목표는 5장. 다른 프로필의 기존 목표 유지 |
| 유입 분석 기간 | 오늘 제외 최근 완료 7일과 이전 7일 비교 | 사용자 지정 기간 우선 |
| 월별 시즌 추천 | 현재 월·현재 연도·8개, 분야 미지정이면 전체 | 지정한 월·연도·분야·개수 우선. 추천만으로 원고를 만들지 않음 |
| 추천 후 작성 | 저장한 번호·주제를 그대로 사용 | 공식 자료 확인·검수·원고 버전·블로그별 이력 저장 |
| 네이버 입력 | `prepare`로 로컬 사전검증 | 실제 입력·임시저장은 명시 요청 시 `draft` |
| 태그 | 고정 개수 없음, 합성 문자열은 #·공백 포함 100자 이하 | 실제 태그 입력 상태를 관찰하며 태그 없음도 확인 결과로 기록 |
| 공개·예약 발행 | 수행하지 않음 | 임시저장·재열기 검증까지가 SmartEditor 실행 범위 |

**참고 글 5개·이미지 5장·제목 후보 5개는 각각 독립된 조건이다.** 시리즈의 15편·3,000자·이미지 최소 3장을 단일 글에 적용하지 않는다. 제목의 혼합형과 이미지의 혼합형도 별개다.

## 3. 단일 글 작성·재작성·문체

[naver-blog-style](../SKILL.md)은 주제와 독자 의도에 맞는 원고를 작성하고 저장된 문체를 적용한다. 기존 글은 요청 범위대로 다듬으며, 다른 작성자의 경험을 자신의 경험으로 만들지 않는다.

```text
$naver-blog-style
주제: 일본 여행 전 준비할 결제수단.
초보 여행자를 대상으로 장단점과 선택 기준을 비교해 작성해줘.
제목은 검색형으로 선정해줘.
```

```text
이 원고를 네이버 블로그 스킬로 재작성해줘.
핵심 내용은 유지하고, 긴 문단과 중복 설명을 정리해줘.
검색 보완은 하지 마.
```

문체 프로필을 새로 정할 때는 7개 차원의 선택형 인터뷰를 사용한다. 한 질문씩 진행하고 말투·리듬·근거·구성을 `always / usually / optional / avoid` 규칙으로 정리한다.

```text
내 네이버 블로그 문체를 설정해줘.
선택지를 한 질문씩 보여주고, 확정한 내용을 스타일 프로필로 정리해줘.
```

## 4. 기존 네이버 블로그 본문 참고

새 정보형·방법형·비교형 원고의 기본 참고는 실제 기존 본문 5개다. 검색 요약만으로 본문을 읽었다고 처리하지 않고, 공통 검색 의도·내용·빠진 정보를 분석한 뒤 공식 자료로 사실을 확인한다. 반복 언급만으로 인기 순위나 특정 국적의 구매 비중을 확정하지 않는다.

```text
돈키호테 쇼핑리스트를 카테고리별로 작성해줘.
기존 네이버 블로그 본문 3개를 참고하고 제품 정보는 공식 자료로 확인해줘.
정보 슬라이드 5장을 생성해 본문에 삽입해줘.
```

```text
네이버 검색 결과의 블로그 본문 5개를 참고해서
오사카 여행 준비 글을 작성해줘.
```

```text
기존 블로그 글은 참고하지 말고 제공한 자료만으로 작성해줘.
```

미지정은 블로그 서비스 검색이고, `네이버 검색 결과를 참고`는 통합 블로그 검색이다. 재작성에는 검색 보완을 요청한 경우에만 적용한다. 개인 경험 후기·일기·문체 인터뷰는 명시 참고 요청이 있어야 적용하고, 제목만·이미지만 요청하면 본문 조사를 생략한다.

명시 N개 중 유효 본문이 부족하면 해당 참고 조건은 미충족이다. 기본 5개에서 일부만 확보했으면 실제 확보 수·누락·잘린 문맥을 밝히고 그 범위로 작성할 수 있다. 이 공통 참고 단계의 현재 연결 대상은 루트와 문답형의 단일 글 작성이며, 모든 연재에 자동 적용된 기능으로 설명하지 않는다.

세부 규칙: [수집·분석 흐름](../references/blog-research-workflow.md) · [입출력 계약](../references/blog-research-contract.md).

## 5. 이미지 계획·생성·삽입·편집

이미지 슬롯은 확정 제목·인접 본문·설명 목적에 맞춰 정한다. 장면·구도·매체를 선택하고 본문 근거에서 카드 제목·요점을 추출해 장별 프롬프트를 조립한다.

| 표현 유형 | 구성 |
|---|---|
| 일반형 `standard` | 문맥에 맞는 사진·일러스트·도해 |
| 정보 슬라이드형 `info-slide` | 표지를 포함한 모든 장을 카드뉴스로 구성 |
| 혼합형 `mixed` | 일반형 표지 1장 + 정보 슬라이드 N−1장 |

| 작업 모드 | 결과 |
|---|---|
| `plan-only` | 슬롯·스토리보드·프롬프트만 준비 |
| `generate-and-compose` | 실제 생성 → 시각 검수 → manifest → 본문 삽입 |
| `edit-existing` | 확인한 원본 이미지를 사용해 요청한 부분 편집 |

주제부터 완성하는 예제:

```text
$naver-blog-style
주제: 돈키호테 쇼핑리스트를 과자·식품·뷰티·생활용품으로 정리.
기존 네이버 블로그 본문 5개를 참고하고 공식 자료로 사실을 확인해줘.
검색과 홈판을 함께 고려한 제목을 적용하고,
정보 슬라이드 / 카드뉴스형 5장을 생성해 본문에 삽입해서 완성해줘.
```

계획·기존 원고·편집 예제는 각각 별도 요청이다.

```text
이 원고에 들어갈 카드뉴스 5장의 구성과 프롬프트만 만들어줘.
이미지는 생성하지 마.
```

```text
이 원고의 제목과 본문을 유지하고 혼합형 이미지 5장을 만들어 삽입해줘.
```

표지와 본문의 비율을 다르게 지정한 정보 도해는 일반형 `standard` 안에서 구성할 수 있다. 아래 예제는 확정 원고에 이미지 5장을 추가하는 요청이다. `info-slide` 및 `mixed`의 본문 카드는 현재 4:5 완료 검사를 사용하므로, 이를 16:9로 자동 전환하는 기능으로 설명하지 않는다.

```text
$naver-blog-style
확정한 M5 Max 로컬 AI 원고의 제목과 본문을 유지하고 이미지만 추가해줘.
카드뉴스 전용 info-slide 대신 일반형 standard의 정보 도해로 구성해줘.
공식 제품 사진을 참고한 간단한 인포 대표 이미지 1장은 1:1,
본문 내용을 설명하는 정보 인포형 이미지 4장은 16:9로 만들어줘.
총 5장을 고품질로 생성하고 검수한 뒤 본문에 삽입해줘.
```

```text
제공한 이미지의 배경만 밝게 수정해줘.
제품 형태와 글자는 유지해줘.
```

N장 완성은 현재 원고에 연결된 **승인된 고유 로컬 파일 N장과 삽입 N개**를 모두 요구한다. 계획·파일 경로·미검수 manifest만으로 완료 처리하지 않는다. 실제 생성·글자·관련성·사실성·비율·묶음 차별성 검수와 로컬 패키지 검사는 별개다.

세부 규칙: [주제부터 이미지 포함 완성](../references/topic-image-completion-workflow.md) · [프롬프트 계약](../references/blog-image-prompt-contract.md) · [manifest v1](../references/image-slot-manifest.md).

## 6. 한 질문씩 선택하는 문답형

[naver-blog-wizard](../skills/naver-blog-wizard/SKILL.md)는 새 글·재작성·이미지만 추가·기존 이미지 편집을 선택해 진행한다. 독자·글 유형·말투·분량·서식과 이미지 없음·프롬프트만·생성·내 파일 사용을 확인하고, 새 원고와 이미지 계획의 사용 선택을 받는다.

```text
$naver-blog-wizard
주제는 일본 여행 전 준비할 결제수단이야.
글쓰기와 이미지 옵션을 한 질문씩 선택하게 해줘.
```

```text
이전 세션을 이어서 진행해줘.
원고는 유지하고 이미지 유형만 카드뉴스형으로 변경해줘.
```

이미 제공한 답은 유지하고, 변경한 옵션에 해당하는 원고·계획·승인만 다시 확인한다. 작업 파일과 세션을 사용자 작업 영역에 보관하며, 결과가 불명확한 생성은 실제 반환 파일과 대조한 뒤 복구한다. 이 스킬에서 문체 인터뷰·시리즈·네이버 입력을 시작하지 않는다.

## 7. 검색형·홈판형·혼합형 제목

[naver-title](../skills/naver-title/SKILL.md)은 검색 의도와 독자의 읽을 이유를 구분해 후보를 만든다. 질문형은 선택 가능한 구조이며 모든 제목의 기본 형태가 아니다. 제목과 본문, 숫자·경험·순위 근거를 대조한다.

```text
네이버 제목 돈키호테 쇼핑리스트
검색형 3개, 홈판형 3개, 혼합형 3개를 만들고
최종 추천과 선정 이유를 알려줘.
```

```text
$naver-title
이 원고에 맞는 홈판형 제목 5개를 만들어줘.
질문형에 치우치지 말고 선택 기준과 차이가 드러나게 해줘.
```

통합 글쓰기는 최종 제목만 원고에 반영하고 후보·선정 메모를 분리한다. 고정 제목은 유지하며, 기존 글의 이미지 전용 요청으로 제목을 바꾸지 않는다.

## 8. 실제 유입 기반 주제·대표 제목 추천

[naver-creator-keyword-recommender](../skills/naver-creator-keyword-recommender/SKILL.md)는 로그인된 크리에이터 어드바이저의 실제 화면을 관찰한다. 검색 유입으로 주제를 정하고 메인 유입으로 제목 패턴을 분석한다. 요청하면 블로그 홈 1~10페이지의 제목 구조도 별도로 분석한다.

```text
$naver-creator-keyword-recommender
내 블로그 [블로그 주소]의 최근 완료 7일 유입을 이전 7일과 비교해줘.
일본 여행 관련 주제 5개와 각각의 대표 제목을 추천해줘.
```

```text
네이버 블로그 홈 1~10페이지의 제목 패턴만 분석해줘.
원문 제목을 복제하지 말고 활용할 수 있는 구조를 정리해줘.
```

| 모드 | 수행 범위 |
|---|---|
| `recommend` | 기본 키워드 추천 + 키워드별 대표 제목 1개 |
| `keywords-only` | 키워드만 |
| `patterns` | 메인 유입 제목 패턴만 |
| `home-patterns` | 블로그 홈 제목 패턴만 |
| `recommend-with-home` | 유입 키워드 + 메인·홈 집계 패턴으로 대표 제목 보완 |
| `title-candidates` | 추가 제목 후보. 개수 미지정 시 키워드별 3개 |
| `full` | 명시한 산출물만 글·이미지·SmartEditor 흐름으로 연결 |

홈 분석의 제목 표본은 검색 키워드로 바꾸지 않는다. 이 기능의 홈 제목 패턴 분석과 단일 글 작성의 기존 게시물 본문 참고는 서로 다른 수집이다. 실제 관찰 범위·부분 수집을 보고하며 검색량·조회수·CTR을 추측하지 않는다.

## 9. 실시간 화제어·기사 홈피드 편집

[moneydaeoebi-homepan](../skills/moneydaeoebi-homepan/SKILL.md)은 실시간 화제어, 기사 URL, 키워드, 소재 카드를 사실 검증부터 제목·원고·이미지 브리프·성과 진단까지 연결한다. 트렌드 순위 관측은 사건 사실의 근거로 쓰지 않고, 비공식 집계면 서비스명·확인 시각·비공식이라는 점을 밝힌다.

```text
$moneydaeoebi-homepan
현재 화제어를 확인하고 R9 10그룹·50개 제목 매트릭스와 TOP5·최종 추천을 만들어줘.
검색어 집계와 사건 사실의 출처를 분리해 검증해줘.
```

모든 제목 생성 요청은 R9 10그룹 × 5개, 총 50개를 출력한다. 그룹마다 따옴표 2개·무따옴표 3개로 구성해 전체 20개·30개를 맞추고, 감정 증폭형을 포함한 10그룹과 30종 스타터를 모두 적용한다. `~라고?`, `~는데?`, `왜 ~지?`, 말줄임표, 감정어 상한과 스타터 라벨을 검사하고, 매니페스트로 주제별 S01~S30 원형·서로 다른 그룹의 TOP5·최종 추천 문장 일치를 확인한다. 민감 소재는 10번 그룹을 추모·의미·공식 대응형으로 대체한다. 원본 R9의 `5%/20% 성과 구간`, `하루 3편`, 유입 경로 합산은 공식 규칙이 아니며 레거시 실험으로 분리했다. `네이버 메인_모바일_홈판`과 `네이버 블로그_모바일`은 기본적으로 따로 기록한다.

원고는 제목의 숨긴 답을 도입 끝에서 첫 소제목 사이에 제공한다. 이미지 생성은 명시 요청에서만 실행하고, 실존 인물 AI 재현과 실제 사건처럼 보이는 합성을 하지 않는다. 실제 게시·예약 발행은 이 스킬 범위가 아니다.

## 10. 연재 기획·원고 작성

[seo-series-writer](../skills/seo-series-writer/SKILL.md)는 니치·전체 목차·제1편부터 시작해 요청 범위대로 이어 쓴다. 전문가형·스토리형·후기형·친숙한 설명형·문제 해결형·비교 선택형 프로필을 지원하고, 미지정은 `expert + friendly`다.

```text
$seo-series-writer
일본 자유여행 준비를 주제로 5편의 목차와 제1편을 작성해줘.
각 편은 다른 질문을 해결하고, 완성형 본문은 3,000자 이상으로 작성해줘.
초보자가 따라 할 순서와 예외 조건을 포함해줘.
```

같은 대화에서 `다음 편`, `제3편 재작성`, `발행 패키지`, `상태 요약`을 요청할 수 있다. 파일 출력 요청 시 공개 본문 `article.md`, 편집 메모 `editorial.json`, 검토 대기 `review.json`을 분리한다. 단독 연재 작성은 개인 문체 자동 적용·이미지 생성·네이버 입력을 기본으로 수행하지 않는다.

## 11. 시리즈 원고·이미지 통합 준비

[naver-series-workflow](../skills/naver-series-workflow/SKILL.md)는 작성 → 내용 검수 → 이미지 계획·생성·검수 → 네이버 정본 준비를 연결한다. 이미지 장수를 지정하면 회차별 수량을 검사하고, 이미지 필수 v2의 최소 3장과 충돌하는 요구는 계약 불일치로 보고한다.

```text
$naver-series-workflow
일본 여행 준비 5편을 네이버용으로 작성해줘.
각 편에 카드뉴스형 이미지 5장을 생성해 삽입하고,
prepare 모드로 검수된 원고와 이미지 패키지를 준비해줘.
```

준비된 원고의 내용·길이·구조·시각·입력 준비 상태를 분리한다. 파일 준비 완료는 실제 업로드·저장 성공이 아니다. `draft`, `resume`, `status`를 지원하며 실제 입력은 대상 블로그와 범위를 지정한 요청으로 연결한다.

```text
검수 완료된 시리즈 1~5편을 [블로그 주소]에 순서대로 입력하고,
각 편을 임시저장한 뒤 재열어 확인해줘.
```

## 12. 완성 원고의 SmartEditor 입력·임시저장

[naver-smarteditor-drafter](../skills/naver-smarteditor-drafter/SKILL.md)는 완성 Markdown 또는 구조형 JSON을 `naver-post/v1`으로 검증한다. 실제 이미지 파일·해시·서식·태그를 확인하며 원고나 이미지를 새로 창작하는 역할은 아니다.

| 모드 | 동작 |
|---|---|
| `prepare` | 로컬 사전검증 |
| `draft` | 실제 입력·업로드·임시저장·재열기 확인 |
| `resume` | 실행 이력과 실제 화면 대조 후 재개 |
| `status` | 로컬 실행 이력 조회 |

```text
$naver-smarteditor-drafter
[원고 파일 절대 경로]와 이미지 패키지를 prepare 모드로 검증해줘.
```

```text
검수된 [원고 파일 절대 경로]를 [블로그 주소]에 입력하고
이미지를 업로드한 뒤 임시저장해줘.
저장한 초안을 재열어 제목·본문·이미지 배치를 확인해줘.
```

실행에는 로그인된 브라우저와 대상 블로그, 로컬 파일 업로드·관찰 기능이 필요하다. 한 편씩 빈 화면 → 입력 → 전체 대조 → 저장 응답 → 재열기 대조 → 새 빈 화면을 확인한다. 저장 여부가 불명확하면 다음 편을 진행하지 않는다. 공개·예약 발행은 수행하지 않는다.

지정한 블로그·카테고리와 실제 태그 상태를 확인하고, 이미지는 정본의 슬롯 순서와 파일 해시에 맞춰 업로드한다. `smarteditor-layout/v2`는 네이티브 표 셀·링크 href·명시 개행·문단 간격을 입력과 재열기에서 각각 검사한다. H2·핵심 요약은 정해진 인용구 서식으로 입력하며, H3·목록·인라인 코드의 문서화된 대체 서식은 실행 기록에 남긴다. 실제 표를 문장으로 대체해 통과시키지 않는다.

저장 후 태그 확인은 `inspect_saved_tags`의 읽기 전용 열기·읽기·닫기로 수행하고 실제 콘텐츠의 전후 동일성을 대조한다. 재개 시 정본 버전·실행 이벤트·작성 잠금과 실제 화면을 확인하며, 저장된 동일 버전을 중복 작성하지 않는다. 세부 계약은 [정본 규격](../skills/naver-smarteditor-drafter/references/naver-post-v1.md), [입력 런북](../skills/naver-smarteditor-drafter/references/smarteditor-runbook.md), [복구 규칙](../skills/naver-smarteditor-drafter/references/recovery-and-safety.md)을 따른다.

## 14. 월별 시즌 추천·작성·갱신·이력

[naver-seasonal-blog-writer](../skills/naver-seasonal-blog-writer/SKILL.md)는 월별 원문 데이터와 블로그별 로컬 작성 이력으로 글감을 고른다. 실제 유입·검색량·경쟁도는 수집하지 않는다. 정제 문구 2,793개, 보수적인 주제 그룹 2,728개를 포함하며 검토 대기 문구 847개를 자동 추천에서 제외한다. 글 작성 전 의미 중복과 실제 해당 연도·회차를 확인한다.

기본 목적은 **해당 월 주제 자동 추천 → 주제 선택 → 실제 글 작성**이다. “이번 달 글 추천”, “3월 주제 추천”처럼 월만으로 요청할 수 있다. 월을 생략하면 현재 월, 개수를 생략하면 8개를 제안한다. 추천 결과의 번호를 지정하면 주제를 바꾸지 않고 글 작성·검수·이력 저장으로 이어간다. CLI도 `recommend` 또는 `recommend --month 3`처럼 날짜 없이 실행할 수 있으며, `--as-of`로 재현할 기준일을 지정할 수 있다.

```text
$naver-seasonal-blog-writer 이번 달에 필요한 주제를 추천해줘.
$naver-seasonal-blog-writer 3월에 쓸 글감을 추천해줘.
$naver-seasonal-blog-writer 추천한 2번 주제로 글을 작성하고 출처·검수·이력까지 저장해줘.
$naver-seasonal-blog-writer 11월 생활정보 글감 8개를 추천해줘. 원고는 아직 쓰지 마.
$naver-seasonal-blog-writer 추천한 동파 예방 주제로 한 편 작성하고 myblog 이력에 남겨줘.
$naver-seasonal-blog-writer 기존 동파 예방 글에 외출 전 체크리스트를 보완하고 새 버전으로 저장해줘.
$naver-seasonal-blog-writer myblog 작성 이력을 보여줘.
```

현재 에이전트가 공식 자료를 실제 읽고 한국어 원고·주장별 근거·본문 위치가 있는 검수 기록을 작성한다. 도우미는 추천 필터·회차·파일 해시·검수 연결·원고 버전과 이력을 처리한다. 자동 검사가 실제 사실성·독창성을 인증하지 않는다. 검색 도구가 없거나 핵심 사실이 미확인이면 needs_review 초안으로 저장하고 완료 원고로 보고하지 않는다.

스킬 폴더 전체만 복사하면 다른 스킬·원본 엑셀·개발 저장소 없이 동작한다. Codex가 실제 작성·내용 검수를 담당하고 Python 3.10+ 도우미가 데이터·파일·이력 계약을 처리한다. 최신 사실 확인에는 웹 검색·읽기 도구를 사용한다. 사용 조건과 월·연도 해석은 [전용 사용 가이드](naver-seasonal-blog-writer-guide.md)에 정리했다.

2026-10-19에 `~/.codex/skills/naver-seasonal-blog-writer/` 전역 설치와 Codex 목록 인식, 설치본의 월별 추천·부가세 원고·검수·이력 저장을 확인했다. 사용자 원고·이력은 스킬 밖 작업 공간에 저장하며 v0001/v0002로 이전 버전을 보존한다. 새 대화의 암묵적 선택·네이버 발행은 미검증이다. 월별 자동 추천은 요청 시 주제 선정이며 정기 발송 스케줄은 설정하지 않았다.

기존 문체 프로필·본문 참고 5개·시리즈 3,000자·이미지 도우미 조건은 이 독립 경로에 적용하지 않는다. 최초 구현은 신규 30개 포함 Python 334개·Node 43개와 외부 사본의 28개 CLI 명령을 통과했다. 후속 월별 기본 동작 보완은 관련 테스트 33개와 12개월 조회를 통과했다. [최초 개발 계획](../dev-plan/implement_20261019_145740.md), [단계별 검증 결과](seasonal-writer-validation-20261019.md)를 참고한다.

| 홈피드 구성·원고 | 제목의 숨긴 답을 도입 끝~첫 소제목에 제공하고 본문 구성 | 선택한 제목으로 홈피드용 원고를 작성해줘. |
| 유입 기반 주제 추천 | 완료된 최근 7일과 이전 7일을 비교해 주제·대표 제목 추천 | 실제 검색 유입을 보고 다음 주제를 추천해줘. |
| 메인 유입·홈 제목 패턴 | 메인 유입과 요청한 홈 1~10페이지의 제목 구조를 집계 | 블로그 홈 제목 패턴만 분석해줘. |
| 수집 범위·근거 표시 | 전체·부분·불가를 구분하고 관찰 점수를 검색량·예측 CTR과 구분 | 누락된 기간과 실제 확인한 근거를 함께 보여줘. |
| 월별 글감·계획 | 월·분야·작성 이력으로 주제 중복을 검토해 추천 | 11월 생활정보 글감 8개를 추천해줘. |
| 추천 번호로 실제 작성 | 앞서 저장한 번호·주제로 공식 자료 확인·원고·검수 연결 | 추천한 2번 주제로 작성해줘. |
| 시즌 원고 갱신·이력 | 이전 버전을 보존하고 블로그별 작성·갱신 이력 관리 | 기존 글을 보완해 새 버전과 이력으로 저장해줘. |
| 연재 기획·프로필·회차 | 전체 목차와 서로 다른 해결 질문, 6종 프로필·다음 편·재작성 지원 | 5편 목차와 제1편을 쓰고 다음 편으로 이어가줘. |
| 콘텐츠 성과 진단 | 관찰 결과·해석 가설·다음 실험 분리, 유입 경로 별도 기록 | 이 성과 자료로 개선 실험을 제안해줘. |

### 이미지 계획·생성·삽입·편집

주요 담당: [단일 글 이미지 흐름](../references/topic-image-completion-workflow.md) · [문답형](../skills/naver-blog-wizard/SKILL.md) · [시리즈 통합](../skills/naver-series-workflow/SKILL.md). 홈피드 편집은 이미지 브리프를 제공하며 실제 생성은 명시 요청에서만 연결한다.

| 기능 | 동작·결과 | 요청 예시 |
|---|---|---|
| 문맥 기반 슬롯 선정 | 확정 H1·인접 본문·독자 이해가 필요한 위치로 삽입 지점 설계 | 설명이 필요한 위치에 이미지 5장을 배치해줘. |
| 본문 근거·제목·요점 추출 | 원고에 있는 정보에서 장별 카드 제목·핵심 요점 추출 | 이 비교 문단을 설명하는 카드 구성을 만들어줘. |
| 이미지 매체·유형 결정 | 자연 실사·정보 도해·창작 콘셉트·일반 UI 개념 중 목적에 맞게 선택 | 준비 순서는 도해, 제품 맥락은 실사로 구성해줘. |
| 장별 프롬프트 조립 | 장면·구도·매체·분위기·설명 목적을 장마다 구체화 | 배경만 바꾼 반복 그림 대신 장별 장면을 설계해줘. |
| 일반형 `standard` | 문맥에 맞는 사진·일러스트·도해 조합 | 일반형 이미지로 구성해줘. |
| 정보 슬라이드 `info-slide` | 표지를 포함한 모든 장을 본문 근거의 카드뉴스로 구성 | 정보 슬라이드 / 카드뉴스형 5장으로 완성해줘. |
| 혼합형 `mixed` | 일반 표지 1장과 본문 정보 슬라이드 결합 | 표지는 일반형, 본문은 카드뉴스로 만들어줘. |
| 계획 전용 `plan-only` | 슬롯·스토리보드·프롬프트·alt·caption까지 준비 | 실제 생성 없이 이미지 구성과 프롬프트만 만들어줘. |
| 실제 생성·합성 | 현재 이미지 도구로 생성 후 시각 QA·manifest·본문 삽입 | 실제 이미지까지 생성해서 글을 완성해줘. |
| 기존 글에 이미지만 추가 | 제목·본문을 유지하고 요청한 이미지만 배치 | 이 원고는 그대로 두고 이미지 5장만 추가해줘. |
| 기존 이미지 편집 | 확인한 원본을 참조해 요청 부분을 편집 | 이 이미지의 배경만 밝게 바꿔줘. |
| 사용자 이미지 가져오기 | 실제 파일을 검사·검수하고 생성 이력과 구분해 삽입 | 내가 제공한 이미지 파일을 순서대로 넣어줘. |
| 참고 이미지·공식 사진 | 실제 참조를 사용하고 화면·제품·사건의 사실성 확인 | 공식 제품 사진을 참고해 대표 이미지를 만들어줘. |
| 장수·비율 지정 | 표지 포함 총 N 확인, 일반형 도해의 장별 비율 요청·검수. 카드뉴스는 4:5 계약 유지 | 일반형 도해로 대표 1:1 한 장, 본문 16:9 네 장을 만들어줘. |
| 실제 시각 QA | 문맥·글자·사실성·손·얼굴·브랜드·모바일 크롭·묶음 차별성 관찰 | 각 이미지의 문구와 주제 관련성을 검수해줘. |
| 실패 슬롯 보정 | 문제가 있는 장만 1회 보정 후 남은 실패 해결 선택 | 3번 카드의 글자 오류만 보정해줘. |
| Manifest·자산 연결 | 슬롯·목적·프롬프트·alt·caption·로컬 파일·승인 상태 기록 | 승인 파일과 슬롯 연결을 확인해줘. |
| 원본 보존·비파괴 삽입 | 원문·기존 파일을 보존하고 이미지 포함 원고를 별도로 출력 | 원본을 덮어쓰지 말고 이미지 포함본을 만들어줘. |
| 정확한 N장 완료 검사 | 승인된 고유 파일 N장과 현재 원고의 삽입 N개를 함께 대조 | 생성 계획이 아닌 이미지 5장 포함 완성본을 전달해줘. |

### 문답·검수·네이버 저장·운영

주요 담당: [문답형](../skills/naver-blog-wizard/SKILL.md) · [시리즈 통합](../skills/naver-series-workflow/SKILL.md) · [SmartEditor 입력](../skills/naver-smarteditor-drafter/SKILL.md). 각 세션·실행의 상태와 실제 결과를 구분한다.

| 기능 | 동작·결과 | 요청 예시 |
|---|---|---|
| 한 질문씩 옵션 확정 | 주어진 답은 재사용하고 미확정 질문만 순차 확인 | 글쓰기와 이미지 옵션을 한 질문씩 물어봐. |
| 원고·작업 선택 | 새 글·재작성·원고 그대로 사용·이미지만 추가·이미지 편집 선택 | 기존 글을 그대로 사용하고 이미지만 추가할게. |
| 옵션 변경·중단·재개 | 세션 revision으로 확정 답과 변경 영향을 추적 | 이전 세션을 이어서 이미지 유형만 바꿔줘. |
| 불명확한 결과 복구 | 미완료 intent와 실제 도구 반환·파일을 대조 | 생성 결과를 확인하고 중단 지점부터 재개해줘. |
| 부분 산출물 복구 | 실패한 메타데이터만 무효화·수정하고 정상 파일 보존 | 잘못된 alt만 고치고 전체 생성은 유지해줘. |
| 공개 본문·편집 메모 분리 | 게시 원고와 근거·검토 대기를 별도 산출물로 관리 | 발행용 원고와 편집 메모를 따로 정리해줘. |
| 네이버 정본 변환 | Markdown·구조형 JSON을 `naver-post/v1`으로 검증 | 이 Markdown을 prepare로 사전검증해줘. |
| 자산 무결성 | 이미지 실파일·크기·SHA-256·승인·요구 장수 확인 | 이미지 누락과 교체 여부를 검사해줘. |
| 회차 범위·품질 게이트 | 요청 회차의 구조·길이·내용·시각·입력 준비를 분리 | 3~5편을 검수하고 입력 준비 상태를 보여줘. |
| 불변 준비 실행 | 기존 run을 보존하고 수정 검토 후 새 run-id로 준비 | 검수 수정분을 새 준비 실행으로 만들어줘. |
| 실제 네이버 입력 | 로그인된 지원 브라우저에서 정본 순서대로 입력·업로드 | 이 완성 원고와 이미지를 인앱 브라우저에 입력해줘. |
| 서식·표시 품질 | 정해진 인용구·네이티브 표·링크·개행·문단 간격 대조 | 표와 출처 링크가 실제 편집기에 보존됐는지 확인해줘. |
| 대상·카테고리·태그 확인 | 지정 대상과 실제 태그 UI를 관찰하고 제한 검사 | 지정 블로그 카테고리 8에 넣고 태그 상태를 확인해줘. |
| 저장 응답 구분 | 임시저장 응답을 기록하고 재열기 성공과 분리 | 입력한 글을 임시저장해줘. |
| 저장 초안 재열기 | 실제 초안을 다시 열어 제목·본문·이미지·서식·태그 확인 | 저장한 초안을 재열어 전체 내용이 같은지 확인해줘. |
| 순차 실행·빈 화면 | 한 편 완료 후 새 빈 편집기 확인, 불명확하면 다음 편 중단 | 1~3편을 한 편씩 저장하고 검증해줘. |
| 읽기 전용 저장 태그 확인 | 태그 열기·읽기·닫기와 실제 콘텐츠 전후 동일성 검사 | 저장 후 본문을 바꾸지 말고 태그만 확인해줘. |
| 버전 대조·중복 방지 | 같은 저장 revision을 재작성하지 않고 불일치는 보고 | 이미 저장한 동일 버전을 제외하고 재개해줘. |
| 실행 이벤트·작성 잠금 | 해시 연결 이벤트·한 블로그 한 작성자 잠금으로 충돌 추적 | 실행 이력을 대조해 현재 작업자를 확인해줘. |
| 상태·작성 이력 조회 | 문답·시리즈·입력 실행 상태 및 블로그별 시즌 로컬 이력 조회 | 완료·대기·실패와 다음 조치를 요약해줘. |

단일 글 작성·이미지 완료·`prepare` 통과는 각각 별도 결과다. 네이버 입력·임시저장을 요청한 실행에서만 브라우저를 조작하며, 완료 보고는 실제 생성·검수·저장·재열기에서 확인한 범위로 한정한다.
