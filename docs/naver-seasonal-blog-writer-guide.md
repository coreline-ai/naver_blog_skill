# 월별 주제 추천·블로그 작성 가이드

기준일: **2026-10-19**. 대상: [naver-seasonal-blog-writer](../skills/naver-seasonal-blog-writer/SKILL.md).

이 스킬의 목적은 **해당 월에 필요한 주제를 자동 추천하고, 선택한 주제로 블로그 글을 작성하는 것**이다. 사용자가 키워드를 직접 준비하지 않아도 시작할 수 있다. 추천만 요청해도 목록·이유·가제를 제공하는 작업이 완결된다.

## 바로 사용하기

설치된 환경에서는 아래 요청을 각각 실행할 수 있다.

```text
$naver-seasonal-blog-writer 이번 달에 필요한 블로그 주제를 추천해줘.
$naver-seasonal-blog-writer 3월에 쓸 글감 8개를 추천해줘.
$naver-seasonal-blog-writer 다음 달 생활정보 주제 5개를 추천해줘.
$naver-seasonal-blog-writer 추천한 2번으로 개인사업자 대상 글을 작성하고 출처·검수·이력까지 저장해줘.
```

설치하지 않은 환경에서는 저장소의 `skills/naver-seasonal-blog-writer/SKILL.md`를 읽고 적용하도록 요청한다. 폴더가 존재하는 것과 호스트가 해당 스킬을 인식하는 것은 구분한다. 이 작업 환경에서는 `~/.codex/skills/naver-seasonal-blog-writer/`에 전역 설치했으며 Codex 목록의 `scope=user`, `enabled=true`와 설치본 실행을 확인했다.

## 추천에서 작성까지

```mermaid
flowchart LR
    A[이번 달·지정 월 요청] --> B[월별 후보·작성 이력 확인]
    B --> C[중복 검토 후 주제·제목·이유 추천]
    C --> D[번호 또는 주제 선택]
    D --> E[공식 자료 확인·실제 원고 작성]
    E --> F[검수·버전·이력 저장]
```

추천 결과에는 번호, 주제·대표 키워드, 가제, 독자의 질문, 해당 월 추천 이유, 작성 시점 제안, 확인할 핵심 사실을 포함한다. “추천한 2번”은 이전 목록의 주제를 그대로 선택한다. 같은 번호를 다른 주제로 바꾸기 위해 재추천하지 않는다. 사용자가 “알아서 하나 골라 작성”까지 맡기면 적합한 주제를 선택해 작성한다.

| 요청 | 처리 |
|---|---|
| 이번 달 주제 추천 | 현재 월의 기본 8개 추천 |
| 3월 주제 추천 | 현재 연도의 3월 추천, 연도·월 표시 |
| 2027년 1월 주제 추천 | 명시한 연도·월을 적용 |
| 다음 달 주제 추천 | 연도 경계를 계산해 다음 달 적용 |
| 12월 월간 계획 | 해당 월의 주제와 작성 순서 제안 |
| 추천한 2번 작성 | 선택한 주제의 실제 본문·근거·검수 작성 |
| 기존 글 보완 | 기존 파일을 읽고 새 버전·검수·이력 저장 |
| 작성 이력 조회 | 지정 작업 공간·블로그의 로컬 기록 조회 |

분야가 없으면 여러 분야에서 추천하며, 분야·문체·독자를 필수 질문으로 요구하지 않는다. 이미 확인한 블로그 성격이나 사용자의 명시 조건을 우선한다. 여러 달을 요청하면 월별로 정리하고 같은 주제의 반복 배치도 검토한다.

월별 자동 추천은 요청한 달에 맞춰 주제를 선정하는 기능이다. 이 스킬만으로 매월 정기 메시지나 예약 발행을 실행하지 않으며, 현재 정기 스케줄은 설정하지 않았다.

## 날짜와 추천 기준

- 월·연도·기준일 미지정은 실행 환경의 현재 날짜를 사용한다. 시간대가 다르거나 재현할 날짜가 있으면 기준일을 명시한다.
- 확인 기준일과 대상 월은 다를 수 있다. 10월에 12월을 기획할 때 현재 자료로 확인하면서 12월 주제를 제안한다.
- 원문에 배치된 월은 실제 신청·행사 일정의 근거가 아니다. 마감·요건·가격 등은 해당 연도의 공식 자료로 확인한다.
- 특정 연도·과거 단기 공지를 다음 해에 자동 전용하지 않는다. 후보가 부족하면 실제 개수와 이유를 알린다.
- 추천 순서는 편집 판단이다. 검색량·경쟁도·노출 점수는 측정하지 않는다.

포함 데이터는 원문 3,109행을 NFC·공백 기준으로 정리한 2,793개 문구와 보수적인 2,728개 주제 그룹이다. 후보 문구 1,946개, 검토 대기 문구 847개를 보존한다. 교정·사업명·행사명 확인이 필요한 문구는 자동 추천에서 제외한다. 모든 검색 의도의 의미 중복을 기계적으로 해결한 데이터라는 뜻은 아니며, 최종 목록은 에이전트가 독자·질문·대상 회차를 비교한다.

## 독립 실행 조건

`naver-seasonal-blog-writer/` 폴더 전체가 배포 단위다. `SKILL.md`, `agents/openai.yaml`, `data/` 3개 파일, `scripts/` 3개 파일, `references/` 3개 파일로 총 11개 파일을 포함한다.

| 항목 | 조건 |
|---|---|
| 작성 주체 | Codex의 현재 에이전트가 실제 원고와 내용 검수를 수행 |
| 로컬 도우미 | Python 3.10+ 표준 라이브러리 사용 |
| 최신 자료 | 사용 가능한 웹 검색·페이지 읽기 도구 사용 |
| 월별 데이터 | 폴더에 정제 데이터 포함. 원본 엑셀·이전 분석 결과 불필요 |
| 다른 스킬 | 개인 문체·제목·시리즈·이미지 스킬 설치 불필요 |
| 사용자 파일 | 스킬 밖 작업 공간에 원고·근거·검수·이력 저장 |

원본 스냅샷을 다시 정제하는 유지보수 작업과 일반 실행은 다르다. 평소 추천·글쓰기에는 포함 데이터만 읽는다. 고정 3,000자, 참고 글 5개, 이미지 5장을 조건으로 요구하지 않는다.

웹 도구가 없거나 핵심 사실을 확인하지 못하면 가능한 범위의 초안을 `needs_review`로 남긴다. 도우미는 파일·출처 연결을 검사하고, 실제 사실성과 원본성 판단은 에이전트가 수행한다. 네이버 로그인·입력·임시저장·공개 발행은 이 스킬의 실행 범위에 포함하지 않는다.

## 원고와 이력

한 블로그 작업에서 식별자가 없으면 `default`를 사용하고 알린다. 여러 블로그는 각각 다른 식별자를 사용한다. 이력 조회 범위는 지정한 작업 공간과 블로그이며, 실제 네이버에 있는 모든 게시물을 자동 수집하지 않는다.

```text
사용자 작업 공간/
├── .seasonal-writer/
│   └── BLOG_ID/history.json
└── articles/
    └── BLOG_ID/post-ID/
        ├── v0001/
        │   ├── article.md
        │   ├── brief.json
        │   ├── editorial.json
        │   ├── review.json
        │   └── receipt.json
        └── v0002/                  # 갱신 시 새 원고·근거·검수
```

article.md는 공개 제목·본문·출처다. editorial.json은 실제 읽은 출처·확인일·주장별 본문 위치·미확인 사항, review.json은 직접 답·제목 일치·실용성·사실 근거·원본성 검수다. brief.json은 선택한 주제·회차·이력 버전을 고정하고 receipt.json은 제출 및 저장 파일을 연결한다.

추천만으로 작성 완료를 기록하지 않는다. 원고가 저장되면 `drafted`, 실제 발행 확인 근거가 있으면 `published`, 변경 사유가 있으면 `needs_update`로 구분한다. 같은 회차의 작성·선택 주제는 신규 추천에서 제외하고 갱신 필요 주제는 updates로 분리한다. 추천 기록 자체는 주제를 영구 제외하지 않는다.

이전에 작성된 다른 표현의 의미 중복은 최종 선정 때도 검토한다. 다른 연도·반기·학기·차수는 실제 대상 기간을 확인해 구분한다. 자세한 상태·회차·파일 계약은 [data-contract.md](../skills/naver-seasonal-blog-writer/references/data-contract.md)를 따른다.

## 로컬 명령 예제

전역 설치본 기준이다. `SEASONAL_WORK_DIR`은 실제 사용자 작업 공간의 절대 경로로 바꾼다. Codex에서 자연어로 요청할 때는 이 값을 직접 입력할 필요가 없다.

```bash
SEASONAL_SKILL_DIR="$HOME/.codex/skills/naver-seasonal-blog-writer"
SEASONAL_WORK_DIR="/absolute/path/to/blog-workspace"

# 이번 달 추천: 날짜·월 생략 가능
python3 -B "$SEASONAL_SKILL_DIR/scripts/catalog.py" recommend \
  --workspace "$SEASONAL_WORK_DIR" --blog myblog

# 지정 월 추천
python3 -B "$SEASONAL_SKILL_DIR/scripts/catalog.py" recommend \
  --month 3 --count 8 --workspace "$SEASONAL_WORK_DIR" --blog myblog

# 연도·월·확인 기준일을 고정한 계획
python3 -B "$SEASONAL_SKILL_DIR/scripts/catalog.py" plan \
  --as-of 2026-10-19 --year 2026 --month 12 --domain 생활정보 \
  --workspace "$SEASONAL_WORK_DIR" --blog myblog

# 이력 조회
python3 -B "$SEASONAL_SKILL_DIR/scripts/history.py" show \
  --workspace "$SEASONAL_WORK_DIR" --blog myblog
```

추천·계획 출력은 JSON이다. 최종 번호와 topic_id를 함께 보존하고, 선택한 주제로 prepare → 에이전트 실제 작성·검수 → commit을 수행한다. 스크립트만 실행해 완성 본문이 자동 생성되는 구조는 아니다. 원고 입력·검수 형식과 작성 명령은 [article-writing.md](../skills/naver-seasonal-blog-writer/references/article-writing.md)를 따른다.

## 확인한 실행 범위

최초 구현은 새 폴더만 복사한 환경에서 12개월·두 블로그·실제 신규/갱신 원고·이력을 검증했다. 이후 전역 설치본으로 10월 추천, 개인사업자 대상 부가세 원고와 근거·검수·이력 저장을 실행했다. 월별 기본 동작 보완 후에는 관련 테스트 33개와 날짜 없는 12개월 추천을 확인했다.

[검증 결과와 로컬 증거](seasonal-writer-validation-20261019.md)에 최초 전체 회귀, 후속 관련 테스트, 전역 목록 인식과 미검증 환경을 구분했다. 배포 스킬 폴더와 ZIP에는 사용자 원고·개인 이력을 포함하지 않으므로 다른 환경에서는 해당 작업 공간의 새 이력으로 시작한다.
