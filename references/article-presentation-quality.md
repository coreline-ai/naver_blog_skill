# 본문 가독성·출처·표 보존

작성·재작성·조사 통합·wizard·시리즈에서 **제목과 공개 본문 확정 전** 적용한다. 기존 글을 몰래 고치거나 새 규칙으로 과거 이미지·원고를 덮어쓰지 않는다.

## 공개 본문 작성

- 우선순위는 이번 명시 요청 → 확인된 개인 프로필 → 공통 기본값이다. 현재 프로필의 출처 기본값은 말미다. 조사용 주장-출처 대응표는 내부 검수 자료이지 문장마다 넣을 링크 목록이 아니다.
- 본문은 공식 기관·자료의 이름과 기준일을 필요한 곳에 자연스럽게 언급한다. 동일 URL을 반복하지 않고 말미 `## 참고자료` 또는 `### 출처`에 설명형 링크로 한 번씩 모은다. 전체 URL을 보이는 본문으로 풀어 쓰지 않는다.
- 사용자가 본문 근처 출처를 명시하면 `--source-placement inline`으로 검증한다. 최신 근거 확인·필요한 주의문·사실은 생략하지 않는다. 출처가 없는 글에 빈 출처 섹션을 만들지 않는다.
- 줄바꿈을 단어 띄어쓰기로 대신하지 않는다. 문단 내부 개행은 원고의 실제 개행으로, 독립 문단은 빈 줄로 구분한다. 짧은 모바일 문단을 사용하고 조사 붙임·단어 띄어쓰기·문장 흐름은 직접 읽어 검수한다. 기계 검사는 한국어 문법 교정이나 사실 확인을 대신하지 않는다.
- 같은 기준으로 비교하는 정보는 `항목 / 조건 / 차이` 등 명확한 열의 Markdown 표 또는 구조형 `table`로 작성한다. 수치를 레이블 문장에 나열하고 표가 있다고 보고하지 않는다. 좁은 화면에서 너무 넓으면 표를 논리적으로 나누고 정보를 삭제하지 않는다.
- 현재 표 셀은 평문이다. 굵은 글씨·링크가 필요한 설명은 표 밖에 두고 셀에는 뜻이 유지되는 평문을 사용한다. 변환기의 `UNSUPPORTED_TABLE_INLINE`을 무시하거나 입력 원고를 무단 수정하지 않는다.

## 순수 준비 검사

`skills/naver-smarteditor-drafter/scripts/presentation_quality.py`를 preflight가 호출한다.

| 진단 | 대응 |
|---|---|
| `INLINE_SOURCE_LINK` | 명시 요청이 없으면 말미로 옮긴 새 원고 버전 작성 |
| `DUPLICATE_SOURCE_LINK` | 같은 URL을 합치고 사실 설명은 유지 |
| `RAW_URL_DISPLAY` | URL 대신 짧고 구체적인 클릭형 출처명 사용 |
| `REFERENCE_SECTION_NOT_TERMINAL` | 공개 본문 뒤로 출처 섹션 정리 |

링크는 최종 텍스트에 URL을 덧붙이지 않고 `link` mark에 저장한다. Markdown 문단 내부 개행·표 빈 셀·행/열 순서를 유지한다. 이 검사는 배치·구조 검사이며 `factual_review=not_evaluated`, `ui_review=not_performed`다.

## SmartEditor 입력과 실제 검수

실제 입력은 [drafter 런북](../skills/naver-smarteditor-drafter/references/smarteditor-runbook.md)을 따른다. `clipboard_renderer.mjs`는 보존형 HTML/text payload만 만들며 UI를 조작하지 않는다.

- 현재 `smarteditor-layout/v2`는 **네이티브 표**를 요구한다. 표 도구 또는 지원 clipboard로 입력한 뒤 실제 table 컴포넌트·셀 배열을 확인한다. 표가 문장으로 붙으면 실패이며 자동 문단 대체는 없다.
- 명시 개행은 `<br>` 또는 지원된 줄바꿈 입력으로 유지한다. 서로 다른 문단 사이에는 빈 문단 또는 실제 양수 간격의 UI 근거를 확보한다. clipboard HTML만으로 네이버의 변환 결과를 보증하지 않는다.
- 입력 직후와 임시저장 재열기에서 `tables / links / line_breaks / paragraph_spacing`을 각각 관찰한다. href·셀·BR·간격을 읽지 못하면 null/unknown으로 멈춘다. 기대값을 관찰값으로 복사하지 않는다.
- 이전 `smarteditor-subset/v1`의 저장 이벤트는 읽기·복구 근거로 보존하지만 새 표시 품질 성공으로 승격하지 않는다. 기존 준비물은 읽기 진단만 하고 자동 재입력·삭제하지 않는다.

완료 보고는 `준비 / 사실 검수 / 이미지 / 입력 / 임시저장 ack / 재열기 / 표시 품질 / 빈 편집기`를 구별한다. 테스트 simulation을 실제 네이버 입력 성공이라고 보고하지 않는다.
