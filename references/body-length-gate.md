# 네이버 본문 분량 게이트

새 완성형 원고의 분량 검사를 내용·이미지 검수와 분리한다. 일반 단일 글과 시리즈에 공통 적용하며 3,000자는 이 프로젝트의 제작 기준이지 네이버 검색·승인 조건이나 품질 보증이 아니다.

## 정책 선택

- `full`: 명시 분량 없는 새 완성형은 본문 3,000자 이상. 미달 시 `failed`, 부족한 근거와 설명을 보강하고 다시 측정한 후에만 이미지 계획·생성, 완료 보고 및 임시저장 handoff를 한다. 간결한 문체·적은 표는 짧은 글 요청이 아니다.
- `explicit`: 사용자가 짧은 글·요약·분량이나 위저드에서 short/medium/long을 명시적으로 선택한 경우. 사용자 분량을 우선하며 측정 결과는 `measured`로 기록한다. 명확한 최소값을 직접 요구한 경우에만 `--minimum N`을 적용한다. 명시된 목표의 충족은 별도로 검토하며 무조건 3,000자 통과로 표현하지 않는다.
- `preserve`: 기존 원고의 이미지 전용, 제목만 수정, 이미 완성된 글의 입력·저장만 요청한 경우. `not_applicable`로 측정만 하며 기준 미달을 이유로 글이나 이미지를 수정하거나 저장을 차단하지 않는다. 기존 자료를 임의 삭제하지 않는다.

본문과 근거를 먼저 다듬고, 제목 확정 뒤 이미지 준비 전에 실행한다. 원고가 바뀌면 결과의 SHA-256은 무효다. 이미지 합성 후나 실제 입력할 정본이 다른 파일이면 그 버전도 검사하고 결과와 SHA를 별도 편집 기록에 보관한다. 실제 UI에서 저장된 글 검증은 별도다. 원고를 읽어야 하며 검사는 원고나 이미지를 수정하지 않는다.

새 이미지 요청 JSON에는 `"body_length_policy": "full"`을 넣어 프롬프트 helper가 동일한 원고를 다시 측정하고 3,000자 미달 계획을 거부하게 한다. 명시 분량·기존 보존에는 각각 `explicit`·`preserve`를 넣는다. 위저드의 신규 등록은 정책을 자동 연결한다. 기존 요청 JSON과의 호환을 위해 필드가 없는 예전 요청은 레거시로 처리하므로, 이 필드가 없는 이미지 helper 결과를 분량 검수 증거로 간주하지 않는다.

```bash
python3 /absolute/project/scripts/check_blog_body_length.py \
  --project-root /absolute/project --input /absolute/work/article.md --mode full
```

Markdown 또는 `naver-post/v1` JSON을 읽는다. 이미지 마커는 측정에서 제거하며 확인된 별도 캡션 블록이 있으면 정본 JSON에서 `--exclude-block-id ID`를 지정한다. 캡션은 식별된 블록만 제외한다. `body_metrics`의 NFKC·공백 정규화 기준으로 제목, 태그, 참고자료, URL, 이미지, alt, 식별된 캡션을 빼고 본문 소제목·문단·목록·표를 센다. 공백 제외 수는 별도 참고값이다. 네이버 UI의 글자 수와 일치한다고 보장하지 않는다.

`passed`는 분량 통과만 의미하며 `meaning_review=not_evaluated`다. 사실·출처, 독자 질문에 대한 답, 예외, 의미 있는 예시·반복 여부는 별도 검수한다. 내용 부족을 반복 문장이나 근거 없는 사실로 채우지 않는다. 추가 근거가 없으면 미완료·조사 필요로 보고한다. 새 독립 SmartEditor CLI는 `full` 분량 검사를 기본 적용하고, 실제 입력 전 `verify_prepared_content.py`로 revision을 재검사한다. `explicit`·`preserve`는 실제 사용자 요청을 별도로 확인하며, 기존 preflight 통과나 분량 검사는 사실성·UI 권한을 뜻하지 않는다. 보고 시 글별 수치·정책·통과 여부와 이미지/저장/재열기 상태를 따로 밝힌다.
