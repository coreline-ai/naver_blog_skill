# 제목 중심 자동 글 구조

## 적용 범위와 우선순위

새 글·요청받은 재작성에 적용한다. 기존 원고의 이미지 작업·SmartEditor 입력만 요청한 경우에는 재분류하거나 본문을 바꾸지 않는다. 저장된 개인 프로필은 말투·리듬·독자 거리의 기준으로 그대로 유지한다. 제목 자동 선택은 **구조** 선택이며 개인 문체나 전문 자격을 바꾸는 기능이 아니다.

우선순위: 이번 사용자의 명시 유형 → 제목의 독자 의도 → 자료와 실제 경험의 범위 → 보수적 정보 정리. 시리즈는 회차마다 판정한다. 이전 회차의 `expert+friendly`를 무조건 복제하지 않는다.

## 자동 진행 순서

1. 제목(없으면 주제/잠정 제목)의 **무엇을 알고 어떤 행동을 하려는가**를 한 문장으로 해석한다. 제목의 단어를 하나 발견했다고 유형을 확정하지 않는다. ‘후기 읽는 법’은 저자의 체험이 아니고 ‘연구로 확인’도 저자가 실험했다는 뜻이 아니다.
2. 아래 구조 중 하나를 고르고 선택 이유를 편집 메모에 기록한다. 비교+체크 등 복합 제목은 주 질문이 primary, 보조 질문은 해당 절로 둔다. 개인 문체는 그대로 입힌다.
3. `scripts/select_article_style.py`에 `title`, `requested_type`, `intent`, `experience_basis`를 전달한다. helper는 로컬 구조·근거 형식만 검증하며 사실 확인·글 생성·원문 열람을 대신하지 않는다.
4. 선택한 흐름으로 실제 원고를 작성하고 제목의 약속·구조·근거를 검수한다. **신규 자동 선택의 최종 기록에는 현재 에이전트가 판단한 intent/reason이 필수**다. `--title`만 실행한 `title_hint`는 초안 후보이며 최종 연결에서 거부된다.
5. 최종 제목이 달라지면 선택기를 다시 실행하고 본문 구성의 적합성도 재검토한다. 제목이 약속한 비교/절차/답이 빠졌으면 먼저 원고를 보완한다. 사용자 고정 제목은 허락 없이 바꾸지 않는다.
6. 본문·제목을 확정한 뒤 기존 출처/표/개행 검수, 이미지 설계·생성·검수·합성으로 이어간다. 별도 ‘유형 확정’ 질문은 만들지 않는다. 필요할 때만 짧게 `비교 분석형 — 같은 조건으로 두 요금제를 비교`처럼 알린다.

## 유형별 구성

| 독자 의도 | article_type | 본문 중심 |
|---|---|---|
| 가격·일정·조건·기본정보 | information | 먼저 답 → 조건별 정보 → 예외 |
| 왜·원리·연구 근거 | expert | 질문 → 근거 → 해석 → 한계 |
| A/B 차이와 선택 | comparison | 공통 조건 → 대칭 비교표 → 상황별 선택 |
| 신청·설치·이용 순서 | howto | 준비 → 순서 → 확인 → 예외 |
| 오류·증상 해결 | troubleshooting | 증상 → 원인 후보 → 확인/조치 → 중단 조건 |
| 실제 제품 사용 평가 | review | 사용 조건 → 실제 관찰 → 장단점 → 적합성 |
| 실제 장소 방문 | place | 방문 조건 → 동선/관찰 → 공식 정보 → 주의 |
| 경험·변화·시행착오 | story | 상황 → 선택/전환 → 결과 → 교훈 |
| 구매·출발 전 점검 | checklist | 우선 항목 → 판단/조치 → 마지막 확인 |

하나의 구조와 기존 primary/secondary 두 프로필까지만 연결한다. `expert`는 근거를 설명하는 방식이지 의사·변호사·전문가 행세가 아니다. 제목에 없는 통계·인기·가격·효과를 채워 넣지 않는다. 표는 비교 축이 있을 때 실제 표로 만들며 모든 글에 같은 FAQ/목차/종결문을 강제하지 않는다.

## 입력·출력 예시

```json
{
  "title": "듀오링고 슈퍼 vs 무료, 뭐가 다를까",
  "requested_type": "auto",
  "intent": {"article_type": "comparison", "reason": "독자가 무료와 유료의 공통 기능과 비용 조건을 비교해 선택하려는 제목"},
  "experience_basis": {"type": "source_based", "evidence": []}
}
```

```bash
python3.11 -B /absolute/package/scripts/select_article_style.py --request /absolute/work/style-request.json
```

stdout 결과를 새 `style-selection.json`에 보존하거나 `editorial.json.style_selection`에 넣는다. `status=ready`는 구조 선택 입력이 유효하다는 뜻일 뿐, 본문 사실/의미/이미지 QA 또는 네이버 입력 승인과 무관하다. 출력의 outline은 편집용 흐름이지 그대로 복사할 고정 소제목이 아니다.

경험 근거는 `source_based`, `user_provided`, `verified_records`, `illustrative`와 근거 설명 배열이다. 사용자 자료·실제 읽은 기록만 사용한다. 일반 웹 후기나 생성 이미지는 저자의 경험 근거가 아니다. `illustrative`는 가정임을 공개한 스토리 사례만 가능하고 후기/방문에는 쓸 수 없다. wizard도 같은 구조 객체를 experience_basis 값으로 받을 수 있다. 가정 사례라는 자유 답변은 illustrative로 보존하고, ‘경험 없음’은 경험 증거로 기록하지 않는다.

`needs_experience`이면 기존 대화/첨부에서 실제 경험을 확인한다. 없으면 정보형 전환 또는 경험 제공 중 필요한 사항만 한 번 묻는다. ‘자료 기반으로’ 동의받아 전환해도 고정 제목의 ‘내돈내산/써보니/후기’가 남으면 `needs_title_revision`이다. 제목 변경 권한 없이 자동으로 고치거나 허구 체험으로 막힘을 풀지 않는다.

## 기존 경로 연결

- 루트 단일 글: 현재 문체를 유지하고 선택 결과를 편집 메모로 보존한다.
- wizard: article_type의 첫 선택지는 `제목에 맞춰 자동 선택`이다. 질문 UI는 미선택을 답으로 처리하지 않는다. auto의 write action은 잠정 후보를 제공하며 최종 article 기록 payload에 위 helper 출력 `style_selection`을 전달한다. `source-based`는 기존 정보형 전환 동의를 유지한다. 이미 승인된 구 세션은 강제 이관하지 않는다.
- 시리즈: 신규 회차마다 `editorial.json.style_selection`을 기록한다. 실제 경험이면 동일한 구조의 `editorial.json.experience_basis`도 기록한다. null로 근거 대조를 생략할 수 없다. prepare는 그 회차의 primary/secondary와 검수 항목을 적용한다. 새 review-template의 `style_selection_sha256`으로 유형·의도·근거 변경 시 과거 의미 검수 승인을 재사용하지 못하게 한다. 기존 manifest 기본 프로필은 호환용이며 선택 기록 없는 기존 준비물에만 그대로 적용한다. 명시 유형이 있으면 각 선택 요청의 requested_type에 반영한다. 세 sibling만 있는 구 설치의 legacy CLI는 유지하며, 새 자동 선택을 쓸 때만 공통 helper가 필요하다.
- 이미지: 유형은 내용의 역할을 전달하는 입력일 뿐 도식/배경/매체 템플릿이 아니다. `image_article_type`으로 기존 이미지 helper의 enum에 연결한다. 인접 절의 목적과 사용자 지정 표현 유형을 우선한다. 기존 이미지 수량·슬롯·태그·출처·표·SmartEditor 안전 기준은 바꾸지 않는다.
- 새 자동 시리즈의 이미지 미지정 목표는 품질을 유지하도록 manifest에 5장으로 명시한다. 이미 정해진 수량은 자동 유형 변경으로 줄이지 않는다.

## 최종 의미 검수

기존 style_fit/title_body_match 검수에 실제 위치로 남긴다: 제목의 주 질문에 답했는가, 선택 구조의 required_checks를 충족하는가, 사실/판단/경험을 구분했는가, 개인 말투를 유지했는가. 근거 없는 `passed`나 반복 검수 문구는 금지한다. 컴퓨터가 문자열·해시를 검사한 것과 에이전트가 글의 의미를 읽은 것은 별개다.
